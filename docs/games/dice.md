# 骰子遊戲

吹牛骰與快艇骰子與骨牌接龍的規則。房間流程、旁觀、計時與 bot：[共通規則](common.md)。

## 吹牛骰

2–8 人淘汰制。每人 5 顆骰子，只看得到自己的；骰盅內的骰子不會送到其他座位。

| 設定 | 規則 |
| --- | --- |
| 人數 | 2–8 個有人座位，出牌順序在 W 之後接續 P5–P8，跳過空位 |
| 骰子 | 每人 5 顆六面骰，每輪全部重新搖；骰子由伺服器以密碼學亂數搖出 |
| 可見度 | 每個座位的骰子數公開；點數只有本人看得到，開之前不會出現在紀錄或其他座位的快照中 |
| 房規 | 沒有可調整的房規 |

1. 第一輪由隨機座位先喊，之後順時針輪流。
2. 輪到自己時，喊「幾個幾點」（所有骰盅合計），或「開」上一位的喊法。第一個喊的人不能開。
3. 喊法必須比上一個更大：個數更多（任何點數），或個數相同但點數更大。點數大小為 2 < 3 < 4 < 5 < 6 < 1，1 點最大；沒有折半或加倍。個數不能超過場上的骰子總數。
4. **1 點百搭**：算進任何點數。有人喊 1 點（叫齋）之後，該輪 1 點不再百搭，只算 1 點本身；喊 1 點本身也只算 1 點。
5. **開**：掀開所有骰盅，統計所喊的點數（百搭時含 1 點）。達到所喊的個數，開的人少一顆骰子；不足，則喊的人少一顆。
6. 輸的人先喊下一輪；若他的骰子已用完，由順時針下一位存活者先喊。所有人重新搖骰。
7. 骰子用完即淘汰，最後留下的人獲勝；越晚淘汰名次越高。

呈現畫格：新一輪 2 秒、喊點 1.3 秒、開 2 秒、掀開骰盅 4 秒（[時間軸](../architecture.md#呈現時間軸)）。「開」的畫格不含結果，掀開骰盅時才依序顯示各座位的骰子、符合所喊點數的骰子、實際個數與輸家。

牌桌顯示目前的喊法、1 點是否百搭、場上骰子數；自己的骰子中符合目前喊法的會標記。名牌顯示剩餘骰子數。骰子以 HTML 與 CSS 繪製，顏色、點與骰盅取自[骰子主題](../../client/src/games/liarsdice/dice-theme.ts)，之後可由骰子外觀系列提供。

## 逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同：喊的個數比期望值高出 1 個以上就開，否則喊最小的合法加碼；第一個喊的人以手上最多的點數開局 |
| 簡單 | 固定門檻，不推測對手（期望值 = 自己的符合骰 + 場上其餘骰子 × 每顆符合的機率） |
| 困難 | 以二項分布估計喊法成立的機率：已知自己的骰子，其餘骰子每顆有 1/6（百搭時非 1 點為 2/6）機率符合 |

[困難策略](../../server/src/bots/liarsdice-strategy.ts)：

- 開的價值是上一個喊法不成立的機率；假設喊的人約一半的機率至少有一顆所喊的點數。
- 加碼的價值是被開時成立的機率，加上沒被開時的固定中性價值；被開的機率依場上骰子數推估。
- 只使用自己的骰子與公開資訊；分數接近的選項會隨機挑選，因此會自然出現虛張聲勢。

## 統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 獲勝時最多剩餘骰子 |
| 紀錄 | 開對、喊的被開仍成立、被開時剛好相符 |
| 其他指標 | 平均損失骰子 |

## 快艇骰子

2–8 人，13 輪計分制。骰子與計分表都是公開的，沒有隱藏資訊；程式碼與介面避免使用商標名稱，50 分格稱為「快艇」。

| 設定 | 規則 |
| --- | --- |
| 人數 | 2–8 個有人座位，出牌順序在 W 之後接續 P5–P8，跳過空位 |
| 骰子 | 每回合 5 顆六面骰，最多擲 3 次；骰子由伺服器以注入的亂數來源擲出（正式環境為密碼學亂數） |
| 房規 | `mode`：`turns`（輪流，預設）或 `simultaneous`（同時），不影響計分 |
| 計時 | 預設 60 秒回合時間加 120 秒時間庫（[`YACHT_TIME_CONTROL`](../../shared/src/games/yacht/definition.ts)） |

**回合**

1. 第一次擲出 5 顆骰子；之後每次擲骰前，點選要保留的骰子（保留狀態公開，其他人看得到），伺服器只重擲沒保留的骰子。5 顆全保留時不能再擲。
2. 擲出第一次後隨時可以計分，不必擲滿三次；每回合必須恰好填滿一個空格，湊不出的格子仍可填入，得 0 分。
3. 輪流模式：座位依序進行，所有人看得到當前玩家的骰子，並在他的列上看到目前骰子填各格的可得分數。同時模式：每一輪所有人各自擲自己的骰子，全員計分後才進入下一輪；自己的骰子顯示在手牌區，其他人以計分表的「已計分」勾與擲骰次數顯示進度。
4. 共 13 輪，每位玩家剛好填滿 13 格。

**計分格**

| 格子 | 得分 |
| --- | --- |
| 一點～六點 | 該點數骰子的總和 |
| 三條、四條 | 至少三、四顆相同時，全部 5 顆骰子的總和，否則 0 |
| 葫蘆 | 三顆同點加兩顆同點：25（五顆同點不算，除非是百搭） |
| 小順、大順 | 四顆、五顆連號：30、40 |
| 快艇 | 五顆同點：50 |
| 機會 | 全部骰子的總和 |

**獎勵與百搭**

- 上半部（一點～六點）合計 63 分以上，加 35 分。
- 快艇格已得 50 分時，每再擲出一個快艇加 100 分，並強制使用百搭規則：對應的上半部格子若還空著，必須填在那格；否則可填任何空的下半部格子，葫蘆與兩種順子照全額計分；下半部都填滿時，只能填空的上半部格子，得 0 分。快艇格填 0 分時，之後的快艇不加分，也不是百搭。
- 總分 = 上半部 + 上半部獎勵 + 下半部 + 100 × 額外快艇。總分最高者獲勝，同分並列獲勝。

呈現：擲出的骰子以 CSS 短暫翻滾（只改 `transform` 與 `opacity`，減少動態效果時直接顯示），不使用伺服器呈現畫格，也不阻擋操作；骰子使用自己裝備的骰子外觀。計分表一列一位玩家，13 格加上半部小計與總分，輪到的玩家（同時模式為自己）的空格顯示目前骰子的可得分數，點選後再按「計入」才寫入。手機橫向 706×336 八位玩家也放得進計分表。

**逾時與 bot**

| 項目 | 規則 |
| --- | --- |
| 逾時 | 輪流模式回合時間用完，或同時模式的整輪期限到：若還沒擲骰就先擲一次，再把骰子寫入最划算的空格（與簡單難度的選格相同） |
| 選格 | 各格的得分減去該格平均得分（[`YACHT_PAR`](../../shared/src/rules/yacht-value.ts)），加上上半部獎勵進度與額外快艇的 100 分，取最高者；百搭規則限制的格子不會被選 |
| 簡單 | 保留數量最多的點數（同數量隨機選一種），沒有明顯好牌就擲滿三次，再用上述選格；擲出的牌型已比平均高出 12 分以上時提早計分 |
| 困難 | 對每種保留方式（最多 32 種）以精確期望值（Expectimax）估算剩餘擲骰後的最佳選格價值，選擇期望值最高的保留方式，或直接計分；價值函數與選格相同，所以會為了上半部獎勵、快艇與順子調整保留 |

困難策略在 [`yacht-lookahead.ts`](../../server/src/bots/yacht-lookahead.ts)；每次決策約數毫秒，不需要 worker pool。測試對固定亂數種子的整場模擬確認困難 bot 的平均總分明顯高於簡單 bot（約 240 對 165），且所有動作合法。

**統計**

| 類型 | 項目 |
| --- | --- |
| 結果 | 單局最高總分、擲出快艇（快艇格加額外快艇）、拿到上半部獎勵 |

## 骨牌接龍

2–4 人，使用 28 張雙六骨牌（兩端各 0–6 點；點數以骰子的點陣繪製）。玩家依序把牌接在同一條龍的兩端，先達到目標分數者獲勝。純規則在 [`rules/dominoes.ts`](../../shared/src/rules/dominoes.ts)。

| 設定 | 規則 |
| --- | --- |
| 人數 | 2–4 個有人座位，座位限 N/E/S/W，不開額外座位；出牌順序 N → E → S → W，跳過空位 |
| 發牌 | 兩人每人 7 張，三到四人每人 5 張，其餘為牌庫；牌序由伺服器亂數洗牌 |
| 可見度 | 手牌只有本人看得到；所有人都看得到每人的張數、牌庫張數、牌龍與紀錄。摸牌只記錄「摸了一張」與當時兩端的點數，不含牌面。觀戰者看得到所有手牌（[上帝視角](common.md#旁觀者與上帝視角)） |
| 房規 | 目標分數 50／100（預設）／150 |

1. **開局**：第 1 局由持有最大雙牌（6-6 到 0-0）的人先出，必須先出那張牌；桌上沒有雙牌時，改由點數最大的牌開局（同點數取較大的一端）。之後每局由上一局的贏家任意先出一張；上一局沒人得分（卡死並列）時，由上一局先手的下家先出。
2. **接牌**：只有一條龍，兩端各開放一個點數（沒有分岔）。牌的一端要和龍端的點數相同才能接；雙牌橫放，但只開放一個點數。一張牌兩端都接得上時由玩家選擇；兩端點數相同時視為同一種選擇，伺服器自動接在右端。
3. **摸牌與跳過**：沒有可接的牌時，必須從牌庫一次摸一張，直到摸到能接的牌並打出；牌庫空了就跳過。手上有可接的牌時不能摸牌或跳過。
4. **單局結束**：有人出完手牌（骨牌），得到所有對手剩餘點數的總和。若牌庫已空且沒有任何人能出牌（卡死），剩餘點數最少者得到所有對手剩餘點數的總和；最少的點數並列則這一局不得分。每局結算公開所有人剩下的牌。
5. **整場結束**：有人在某一局後累計達到目標分數，整場結束，總分最高者獲勝，同分並列獲勝，其餘依總分排名。為避免連續無人得分，整場最多 30 局；達到上限時同樣以總分最高者獲勝。

呈現畫格：發牌 1.5 秒、單局結算 5 秒（[時間軸](../architecture.md#呈現時間軸)）；出牌、摸牌與跳過直接更新牌桌，不佔用畫格。

牌桌以 HTML 與 CSS 繪製骨牌，顏色與點取自[骰子主題](../../client/src/games/liarsdice/dice-theme.ts)，因此會套用自己裝備的骰子樣式（[外觀商店](../interface.md#外觀商店)）。牌龍會自動縮放並折返成蛇形，使完整的 28 張牌也能在手機橫向 706×336 內看清；左右兩端以虛線方塊標示點數，選到可接兩端的牌時兩端亮起，點端點決定接法。只能接一端的牌點一下直接打出。手牌最大的在左（[`HandSortRules.initial`](../../client/src/games/client-game.ts)）。沒有可接的牌時，牌庫變成「摸牌」按鈕，牌庫空了則顯示「跳過」。每局結算以呈現畫格顯示所有人剩下的牌、點數、本局得分與總分；整場結束時的結算對話框列出每局得分。

## 骨牌接龍的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 打出點數最大的合法牌（接哪一端取第一個合法端）；沒有可接的牌則摸牌或跳過 |
| 簡單 | 隨機選一張合法牌與一端；沒有可接的牌就摸牌或跳過 |
| 困難 | 啟發式評分，分數接近的選項隨機挑選 |

[困難策略](../../server/src/bots/dominoes-strategy.ts)只使用自己的手牌與公開資訊：

- 優先打出點數大的牌與雙牌（少留負擔），對手手牌剩 2 張以下時更重視減少手上點數；能出完就出完。
- 保留點數種類多的手牌，並偏好讓龍端留在自己還有牌可接的點數上。
- 公開推論：對手摸牌或跳過時，當時兩端的點數就是他沒有的點數（之後摸到的牌未知，所以摸牌會重置這個推論）；盡量把龍端留在對手缺的點數，也避開場上與自己手上未見牌很多的點數。
- 決策時間遠低於 50 毫秒，不使用 worker。
