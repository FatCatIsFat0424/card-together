# 棋類遊戲

各棋類的規則。認輸、提和、計時、視角與手數紀錄：[棋類共通](common.md#棋類共通)；介面：[棋盤牌桌](../interface.md#棋盤牌桌)。

## 黑白棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 8×8，固定不旋轉，下方為 1 列、左方為 a 行；手數以座標記錄（`d3`），無子可下記為「跳過」 |
| 開局 | d4、e5 為白，e4、d5 為黑；座位順序在前的玩家（N、E、S、W 之順）執黑先手 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 沒有可調整的房規 |

1. 每步下在空格，並在至少一個方向（橫、直、斜）上夾住連續的對手棋子，其中必須至少夾住一子；被夾住的棋子全部翻成己色。同時夾住多個方向時一併翻轉。
2. 沒有合法位置的玩家自動跳過，由對手繼續下；伺服器在對手落子後立即記錄跳過，牌桌顯示「無子可下，跳過」，直到下一手為止。
3. 雙方都無子可下時結束（通常是棋盤下滿，也可能提早）。棋子較多者獲勝，數量相同為和局。
4. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
5. 逾時由 bot 代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（子數較多、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內查開局庫，否則迭代加深搜尋（時間 2 秒），剩 20 格以內改為證明勝負；沒有 worker 或搜尋失敗時改用同步版本（開局庫、4 層搜尋，剩 12 格以內證明勝負） |

[bot 策略](../../server/src/bots/reversi-search.ts)：

- 盤面用 64 位元棋盤（兩個 32 位元整數）表示，落子與翻子不配置記憶體（[`reversi-board.ts`](../../server/src/bots/reversi-board.ts)）。
- 中盤：PVS（主要變例搜尋）加置換表、根節點期望視窗與 Multi-ProbCut（淺層搜尋已明顯超出視窗時提前剪枝）；走法排序依序為置換表最佳步、淺層評估，接近葉節點時改用「讓對手行動力最少」。迭代加深用完整個預算，時間到時採用最後完成的一輪；未完成的一輪若已證明另一步較好也會採用（[`reversi-engine.ts`](../../server/src/bots/reversi-engine.ts)）。
- 評估：邊、角（3×3、2×5）、各橫列與斜線的棋型表，加上雙方行動力與空格奇偶，每 5 個空格一組權重（[`reversi-eval.ts`](../../server/src/bots/reversi-eval.ts)）。棋型的 8 種對稱共用同一組權重。
- 終盤：剩 20 格以內先用少量時間（剩 19–20 格時約四分之一）做中盤搜尋排序，再以零視窗證明每一步的勝、和、負，選第一個必勝步，其次必和步；全部必敗或時間不夠時採用中盤結果。證明時依「對手行動力最少」排序（剩 14 格以上再加上評估），剩 6 格以內改用區域奇偶排序並略過置換表。比賽只看勝負，所以只證明勝負，不追求最大子數差。
- 開局庫：開局前幾手的局面（含對稱）以較深的離線搜尋選好一步（[`reversi-book.ts`](../../server/src/bots/reversi-book.ts)）。
- 同步版本與 worker 共用同一個引擎與資料，只限制深度，保持廉價。只使用盤面這份公開資訊；同一局面的選擇固定。

離線資料（[`scripts/reversi-training/`](../../scripts/reversi-training/train.ts)）：

| 檔案 | 產生方式 | 重新產生 |
| --- | --- | --- |
| [`reversi-weights.bin`](../../server/src/bots/reversi-weights.bin) | 自我對局：隨機開局幾手後雙方以 2–6 層搜尋對下，剩 14 格時精確解出最終子數差，作為之前所有局面的標記；剩 14–8 格的局面各自精確求解。以隨機梯度下降擬合棋型權重，下一輪用新權重再對下，共 7 輪、每輪 24,000 局；第 4 輪起標記改為對局結果與當時搜尋分數各半，降低雜訊。只存每個對稱類別一個值，16 位元整數 gzip 壓縮（約 0.6 MB） | `npm run reversi:train`（約 2.5 小時，6 個子程序；中斷後可續跑） |
| [`reversi-probcut.ts`](../../server/src/bots/reversi-probcut.ts) | 1,000 個自我對局局面上比較 3–11 層與對應淺層搜尋的值，依 5 個階段擬合線性關係與標準差；超出視窗 1.5 個標準差才剪枝 | 權重更新後執行 `npm run reversi:probcut`（約 3 分鐘） |
| [`reversi-book.bin`](../../server/src/bots/reversi-book.bin) | bot 執黑或執白的前 5 手：自己照開局庫走、對手任意應手時會遇到的所有局面（合併對稱後 1,432 個，24 KB），各以 20 層搜尋選步；即時搜尋在開局約 15–18 層 | 權重與 ProbCut 更新後執行 `npm run reversi:book`（約 35 分鐘，10 個子程序） |

權重或開局庫缺檔、格式不符時直接報錯。worker 內的中盤與終盤置換表各 2^18 項（合計約 12 MB，跨任務沿用），權重展開後約 4 MB。改動棋型、階段或評估單位後須依序重跑三個指令並提交新檔案；中間的對局資料快取在 `node_modules/.cache/reversi-training`，不提交。

強度：2 秒預算下中盤約 13–20 層（約每秒 100 萬個節點，ProbCut 讓深度多出約 3 層），剩 20 格證明勝負平均約 0.6 秒。對戰場對上一版（迭代加深 alpha-beta）：每步 300 毫秒 200 局全勝、正式預算 24 局全勝；開發中每輪權重與 ProbCut 也都以對戰場確認（例如第 4 輪權重對第 1 輪 83%、加上 ProbCut 對不加 71%）。

### 黑白棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 終局最多棋子、全滅對手（可回放） |
| 紀錄 | 佔據角落、單步最多翻子 |

## 鬥獸棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 7×9，雙方半場各有一條河（2×3 兩塊水域）、三個陷阱與一個獸穴；依視角旋轉，自己永遠在下方，棋子文字保持正立；座標以先手視角標示（左下 a1、右上 g9） |
| 棋子 | 每方 8 隻：象 8＞獅 7＞虎 6＞豹 5＞狼 4＞狗 3＞貓 2＞鼠 1；開局為點對稱的標準排法，棋子上標示動物與等級數字 |
| 先手與顏色 | 座位順序在前的玩家執紅、先手、從下方出發；另一方執藍 |
| 手數紀錄 | 動物加座標（`象g3-g4`；吃子為 `象g3xg4`；英文用兩字母縮寫，如 `El g3xg4`） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 沒有可調整的房規 |

1. 每步走一隻棋子，上下左右一格；不能走到有自己棋子的格子，也不能走進自己的獸穴。
2. 等級相同或較低的棋子可以吃；例外是鼠可以吃象，象不能吃鼠。
3. 只有鼠可以進入河中（水域）。**河中與岸上不能互吃**：河中的鼠不能吃岸上的棋子（包括象），岸上的棋子（包括鼠）也不能吃河中的鼠，鼠不能以吃子的方式離開水域；兩隻同在河中的鼠可以互吃，鼠可以走到空的岸上格。
4. 獅、虎可以沿直線跳過河（橫向跳過 2 格水域、縱向跳過 3 格水域），落點為空格或可吃的敵子；跳越的水域中只要有任何一隻鼠（不論敵我）就不能跳。
5. 棋子在對方陷阱內時等級視為 0：任何棋子都能吃它（象也能吃陷阱內的鼠），它自己吃不了任何棋子（陷阱內的鼠也不能吃象）；離開陷阱即恢復原等級。自己的陷阱對自己沒有影響。
6. 勝負：走進對方獸穴者勝；吃光對方所有棋子者勝；走完後對方沒有任何合法步者勝。
7. 和局：連續 100 手（雙方各 50 手）沒有吃子，判「無吃子和局」。不另設重複局面規則。
8. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
9. 逾時由 bot 代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（進入獸穴、棋子全被吃光、無子可動、無吃子和局、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 鬥獸棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內迭代加深的 PVS alpha-beta（時間 2 秒，不設深度上限，開局約可算 12 層以上）；沒有 worker 或搜尋失敗時改用同步版本（4 層、小型置換表） |

bot 策略（[搜尋](../../server/src/bots/jungle-search.ts)、[盤面與走法表](../../server/src/bots/jungle-board.ts)、[評估](../../server/src/bots/jungle-eval.ts)）：

- 盤面用型別陣列，河、陷阱、獸穴與獅虎跳河都預先算成表，走子與還原不配置記憶體；搭配 Zobrist 置換表、killer、history、晚期走法縮減（LMR）與 aspiration window。
- 對方棋子站在己方獸穴旁的陷阱格時，下一手即進穴，只考慮能吃掉它的走法；己方棋子站在對方獸穴旁則直接判勝。葉節點接只含吃子的靜態搜尋。
- 評估 = 子力（陷阱內只算部分）＋依真實路徑距離（河、鼠游水、獅虎跳河）的前進分＋獸穴賽跑（我方走到對方陷阱格的步數，與對方守子走到該格鄰格的步數比較）＋己方陷阱格的守備覆蓋＋鼠象相剋（敵象在場時鼠加分，敵鼠在場時象扣分且越近扣越多）。殘局的前進分加權；接近 100 手無吃子時評分向和局衰減。
- 從 log 還原上次吃子後的盤面與無吃子手數：搜尋中滿 100 手視為和局，重複局面也視為和局（遊戲本身沒有重複局面規則，這只用來避免原地打轉）。
- 贏棋的評分依手數遞減，使搜尋偏好最快的勝利與最慢的失敗；評估帶極小的隨機擾動，讓相同局面不會總走同一步。
- 權重由 [`scripts/jungle-tune`](../../scripts/jungle-tune/tune.ts) 以自對弈 SPSA 離線調整，結果存於 [`jungle-weights.ts`](../../server/src/bots/jungle-weights.ts)。

### 鬥獸棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 進入獸穴獲勝（可回放） |
| 紀錄 | 單局最多吃子、以鼠吃象、跳河次數 |

## 五子棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 15×15 交叉點（[棋盤](../../shared/src/rules/board/boards.ts)），固定不旋轉，下方為 1 列、左方為 a 行；手數以座標記錄（`h8`） |
| 先手 | 座位順序在前的玩家執黑先手，之後輪流落子 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 連珠禁手（預設關）、交換開局（預設關）；兩項都會讓準備狀態失效，開局後不能更改 |

1. 每手下一子在空的交叉點，下了不能移動或收回。
2. 預設為無禁手：橫、直、斜任一方向連成五子或更多（長連也算）即獲勝，黑白皆然。
3. 棋盤下滿仍無人連成五子為和局。
4. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
5. 逾時由 bot 代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（連成五子、棋盤下滿、認輸、雙方同意和局）與子數；獲勝的五子在盤面上加框。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 房規

| 房規 | 內容 |
| --- | --- |
| 連珠禁手 | 只限制黑棋：長連（六子以上）、雙四、雙三的位置不能下，伺服器直接拒絕，牌桌上輪到黑棋時以紅叉標示。黑棋必須恰好連成五子才算贏，白棋五子以上都算贏。下出恰好五子的位置永遠合法，即使同時形成雙三、雙四或長連 |
| 交換開局 | 採標準「交換」（swap）：先手玩家依序下黑、白、黑三顆開局子，後手玩家再選顏色。選執黑代表與先手交換，選執白則維持原樣；之後由白棋先下。座位順序不變，只有顏色互換，結算會記錄誰執黑 |

禁手判定（[規則](../../shared/src/rules/gomoku.ts)）：

- 四：下這一子後，再一子就能連成恰好五子的棋型；一排「活四」（兩端都能成五）只算一個四，同一排兩處獨立的缺口則算兩個四。
- 三：再一子就能變成活四的棋型，且那個活四的落點本身必須合法（不是長連、雙四或雙三）；有一端被擋住的三、貼著邊界無法延伸的三都不算活三。
- 雙四與雙三不論是否同一子造成都禁止；四三（一個四加一個活三）合法。長連加上另一個方向的恰好五子，視為五子獲勝。
- 若黑棋輪到時所有空點都是禁手（只可能發生在幾乎下滿的棋盤），視為棋盤下滿的和局。

交換開局期間，輪到的玩家可以認輸或提和；逾時時，先手玩家由 bot 代下開局子，後手玩家由 bot 代為選色。

### 五子棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（含交換開局的開局子與選色）（[搜尋與落子時間](common.md#bot)） |
| bot | 只有一個強度。在 bot worker 內先做威脅搜尋，再做迭代加深的 alpha-beta（時間 2 秒、深度上限 24 層）；沒有 worker 或搜尋失敗時改用同步版本（同一搜尋，限深度 4 層與 2,500 個節點） |

[bot 策略](../../server/src/bots/gomoku-search.ts)：

- **棋型表**（[棋型](../../server/src/bots/gomoku-patterns.ts)、[盤面](../../server/src/bots/gomoku-position.ts)）：每個空點、每個方向（橫、直、兩斜）、每一方，都用以該點為中心的 9 格視窗查表，得到「這一方下在這裡會形成什麼」：五、活四、四、活三、眠三、活二、眠二。落子與還原只更新周圍最多 32 個點的視窗，並同步維護棋型計數、能成五／成四／成活三的點集合、候選點（棋子兩格內）與 Zobrist 雜湊。表格第一次用到時才計算，worker 啟動不受影響。
- **評估**：己方所有可形成的棋型依強度加權相加，減去對手的 0.7 倍（輪到己方先動）。連珠禁手下，黑棋的成五與禁手一律用[共用規則](../../shared/src/rules/gomoku.ts)確認，棋型表只負責篩選。
- **威脅搜尋**（[威脅](../../server/src/bots/gomoku-threats.ts)）：
  - VCF：攻方只下四，守方只有一個補點（或無解）；守方補點讓對手形成四時，攻方必須回應。
  - VCT：攻方可以下四與活三；守方只考慮能形成四的點（涵蓋所有活三的封堵與反擊的四）。
  - 黑棋只走合法點，守方是黑棋而補點為禁手時視為守不住；黑棋的「雙四」若是禁手則不算。
  - 用途：根節點先找己方必勝（找到就直接走）、再剔除讓對手 VCF／VCT 必勝的候選著；每個葉節點先跑一次小型 VCF。節點數與時間都有上限（根節點的威脅搜尋最多用三分之一的時間），超過只會判成「沒找到」。
- **alpha-beta**：negamax＋PVS、Zobrist 置換表（worker 內跨手共用，連珠規則改變時清空）、killer 與 history 排序、晚著縮減。
  - 對手有必勝威脅（活四點、雙四、四三）時只考慮能形成四的點，這包含所有守法；其餘節點保留所有能形成或阻止活三以上的點，再加上最佳的幾個安靜著，所以不會剪掉必要的防守。
  - 只有一個回應時（對手有四）不消耗深度。
- **開局**：第一手下天元；第二手在對方棋子旁隨機一格；前幾手在近似的最佳著中隨機挑選，讓對局不重複。
- **交換開局**：先手座位的 bot 依序下天元、旁邊一格，第三子在天元周圍兩格內逐一試下並搜尋，選白棋形勢最接近均勢的點（後手座位會挑較有利的一方，所以不讓出優勢）；後手座位的 bot 搜尋白棋在此局面的形勢，白棋較差就執黑，接近均勢時各半。
- 搜尋在期限前約 100 毫秒結束，並預留 worker 第一次載入模組的時間。
- 測試（[威脅搜尋](../../server/tests/runtime/gomoku-threat-search.test.ts)、[策略](../../server/tests/runtime/gomoku-bot-strategy.test.ts)）涵蓋棋型分類、已知的 VCF／VCT、必須補的四與活三、禁手規則、增量狀態與還原、節點與時間預算。對舊版的強度用 [Bot 對戰場](../development.md#bot-對戰場)驗收（`--game gomoku`，`--options` 可測連珠禁手與交換開局）。

## 圍棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。規則實作：[`go.ts`](../../shared/src/rules/go.ts)（提子、自殺、劫、讓子、數子）、[`go-match.ts`](../../shared/src/rules/go-match.ts)（紀錄重播、點目期限）。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 9、13 或 19 路交叉點（[棋盤](../../shared/src/rules/board/boards.ts)），固定不旋轉；座標欄字母跳過 I（`D4`），列數由下往上；星位依路數標示（9 路 5 個、13 路 5 個、19 路 9 個） |
| 先手 | 座位順序在前的玩家執黑；不讓子時黑先，讓子時白先 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫；點目有自己的共用期限（見下） |
| 房規 | 路數（預設 9 路）、讓子（不讓，或 2 至 9 子；9 路最多 5 子，切換成較小的棋盤會自動降低）；兩項都會讓準備狀態失效，開局後不能更改 |

1. 每手下一子在空的交叉點，或停一手；下了不能移動或收回。
2. 棋子與相連的棋塊需要至少一口氣（相鄰的空點）。一手棋讓對手棋塊失去最後一口氣時，該棋塊被提走。下在沒有氣的位置（自殺）不允許，除非同時提子。
3. 劫：局面超級劫（positional superko）。不能下出讓棋盤回到先前任何一個出現過的局面（不分輪到誰），一條規則同時涵蓋單劫與循環劫。牌桌上不會標示劫的位置，這些點不能點選。
4. 雙方連續停一手，或手數達到「棋盤點數 × 3」（9 路 243、13 路 507、19 路 1083；停一手也算），對局停止並進入點目。
5. 可隨時認輸（包含點目期間）。不開放提和：貼目 .5 讓對局沒有和局。
6. 逾時由 bot 代走一步；只有沒有合理落點時才停一手，不會因超時判負。

### 點目

進入點目後，伺服器先用形勢估計（[`go-ownership.ts`](../../shared/src/rules/go-ownership.ts)：無條件活棋判定、輕量模擬的歸屬機率、被圍住的棋塊）標出它認為的死子，新手不必自己判斷死活。

| 步驟 | 規則 |
| --- | --- |
| 切換死活 | 任一方點選棋塊（整塊相連的同色棋子）即可標為死子或改回活子；任何切換都會清除雙方的確認 |
| 確認 | 雙方各自確認；確認時要附上自己看到的死子清單，標記在這之後有變就會被拒絕（「標記已變更」），所以不會因為對手最後一刻切換而確認到自己沒看過的結果 |
| 繼續下棋 | 任一方可選擇回到對局，由最後停一手者的對手先下，停一手計數重新開始，回合計時從先下的玩家重新起算；已達手數上限的對局不能繼續 |
| 期限 | 雙方共用一個期限：房間的回合時間加時間庫，至少 90 秒、最多 180 秒（[`goMarkSeconds`](../../shared/src/rules/go-match.ts)）；期限一到，尚未確認的真人視為接受目前的標記，bot 照自己的判斷回答 |
| 計分 | 雙方都確認後以中國規則數子：活子加上只被自己圍住的空點（接觸雙方的空點不算）；死子先從盤面拿掉；提子數只是紀錄，不計入勝負。白棋加貼目 7.5，有讓子時只加 0.5 |

結算顯示勝負、勝多少目、雙方目數與貼目、手數與共提子數；死子在終局盤面上半透明，雙方圍住的空點與死子位置以小方塊標示歸屬。對局紀錄的原因是「點目勝」（`score`）；手數達上限後計分則記為「達到回合上限」（`move-limit`），認輸為「認輸」。

階段：`playing`（對局）→ 兩次停一手或達手數上限 → `marking`（點目）→ 雙方確認 → `scoring`（本平台所有遊戲的「已結束」階段名）；`marking` 選擇繼續下棋則回到 `playing`。點目中沒有單一回合，所以座位時鐘停止；它使用[共用期限](common.md#出牌計時)，與陸戰棋布陣相同的機制。

### 讓子

固定擺在星位，由下方看：2 子為左下與右上，3 子加右下，4 子四角，5 子加天元，6 子四角加左右邊星，7 子加天元，8 子四角加四邊星，9 子全部。黑棋（座位順序在前者）先擺好，白棋先走，貼目降為 0.5。只有執黑的勝場計入「讓子勝場」統計。

### 圍棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走一步；不會因此停一手（除非沒有合理落點）（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內做蒙地卡羅樹搜尋（UCT + RAVE），用滿 2.5 秒的時間上限（最佳一手已不可能被超越時提早結束）；沒有 worker 或搜尋失敗時改用同步版本（同一搜尋，最多 300 次迭代或 60 毫秒；點目檢查的模擬也限 60 毫秒） |

[bot 策略](../../server/src/bots/go-search.ts)：

- 搜尋樹（[`go-mcts.ts`](../../server/src/bots/go-mcts.ts)）：節點放在一次配置好的 typed array（約 52 萬個節點、17 MB），記憶體不隨路數或思考時間增加；節點累積 8 次模擬後展開。子節點的先驗（虛擬勝負）來自提子、逃叫吃與征子判斷、MoGo 3×3 棋形、與上一手的共同命運圖（同一棋塊算一步）距離、空曠處的一二線扣分與三線加分，以及離線擬合的走法模型。選點只看勝率與 RAVE（AMAF），不另加探索項。
- 模擬（[`go-playout.ts`](../../server/src/bots/go-playout.ts)）：MoGo 式的重模擬，依序嘗試：上一手附近的叫吃（提子；逃跑前先讀征子，逃不掉就不逃；兩氣棋塊征得到就征）、全盤被叫吃的棋塊、上一兩手的最後好應手（last-good-reply）、上兩手附近的 MoGo 棋形，最後才是不填自己眼、不送多子被吃的隨機點。
- 走法模型：[`scripts/go-model/`](../../scripts/go-model) 用 bot 的自我對局紀錄，以 Coulom 的 MM 演算法擬合 3×3 棋形、提子／逃跑／叫吃、送吃、線位與距離特徵的強度，結果在 [`go-model-weights.ts`](../../server/src/bots/go-model-weights.ts)。重新產生時，每個核心跑一個 `selfplay.ts`（用法見檔頭），再用 `fit.ts` 讀所有紀錄覆寫權重檔。
- 開局（[`go-opening.ts`](../../server/src/bots/go-opening.ts)）：9 路黑棋第一手下天元；13、19 路在開局階段，角落還空著、盤上也沒有兩氣以下的棋塊時，佔一個空角的星位或小目。之後都交給搜尋。
- 讓子：模擬以動態貼目計分，開局時黑棋要多贏每子 7 目，隨手數線性降到 0（手數達盤面點數一半時）。白棋的勝率因此不會一開始就接近 0 而亂下，黑棋也不會因為領先而鬆懈。
- 停一手：沒有合理落點時停一手；對手停一手後，若現在計分（用伺服器同一套死子估計，取同一個亂數種子）已經會贏就跟著停，否則繼續下（例如把留在自己地裡的死子提掉）。對手沒停時，只有局面已定、停一手的勝率不輸最佳一手，而且對手跟著停的計分會贏時才停。
- 點目：bot 用自己的重模擬估計檢查標記。被標成死子的己方棋塊其實是活的（無條件活，或歸屬機率至少 70%），或目前標記會輸、而把它估計為死子的對方棋塊也算死就會贏時，選「繼續下棋」把棋下清楚；否則確認。每場最多這樣爭議 2 次（[`GO_MAX_CONTESTS`](../../server/src/bots/go-search.ts)），之後一律接受，避免兩個 bot 互相爭議到手數上限。真人逾時未確認也接受目前標記。

bot 以勝率而非目數為目標：大幅領先時會下得保守，落後時會冒險。9 路最強；19 路每個落點分到的模擬較少，大局與死活仍可能看錯。

## 象棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。規則實作：[`xiangqi.ts`](../../shared/src/rules/xiangqi.ts)。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 9 路 × 10 線交叉點，楚河漢界與雙方九宮；依視角旋轉，自己永遠在下方，棋子文字保持正立；下緣標示自己這一方的路數（紅方一～九、黑方 1～9，各自從右數起） |
| 棋子 | 紅：帥、仕、相、俥、傌、炮、兵；黑：將、士、象、車、馬、包、卒 |
| 先手與顏色 | 座位順序在前的玩家執紅、先手；有讓子時仍由紅方先走 |
| 手數紀錄 | 繁體中文用中文記譜，英文用 WXF 記譜（見下方） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 讓子（見下方），預設不讓子 |

1. 走法：帥（將）、仕（士）只在九宮內走，帥直橫一步、仕斜一步；相（象）斜走兩步，中間有子（塞象眼）不能走，不能過河；傌（馬）先直橫一步再斜一步，第一步有子（蹩馬腳）不能走；俥（車）直橫不限距離；炮（包）移動同車，吃子必須隔恰好一子；兵（卒）向前一步，過河後也可以橫走一步，不能後退。
2. 雙方將帥不能在同一路上直接相對（中間沒有棋子），任何一步都不能讓自己的將帥處於被將軍的狀態；伺服器拒絕這類走法，牌桌也只顯示合法落點。
3. 將死對方獲勝；輪到的一方沒有合法步時，即使沒被將軍也判負（困斃）。
4. 長將判負：同一局面（含輪到哪一方）第 3 次出現時，若某一方從該局面第一次出現起的每一步都在將軍，該方判負；雙方都一直將軍，或沒有任何一方一直將軍，判「重複局面」和局。
5. 雙方共 120 手（各 60 步）沒有吃子，判「無吃子和局」。
6. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
7. 逾時由 bot 代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（將死、困斃、長將判負、重複局面、無吃子和局、認輸、雙方同意和局）與手數（雙方合計）。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 與正式賽規的差異

亞洲象棋聯合會與中國象棋協會的正式規則對重複局面有細緻的裁決，本遊戲採簡化規則，由伺服器自動判定：

| 項目 | 正式賽規 | 本遊戲 |
| --- | --- | --- |
| 長將 | 單方長將判負 | 相同：第 3 次出現同一局面時，期間每一步都將軍的一方判負 |
| 長捉（反覆捉子）、一將一捉等 | 依「禁止著法」判負或變著 | 不判；只要不是單方長將就以重複局面和局 |
| 雙方都違規或都不違規 | 依細則判和或要求變著 | 一律和局 |
| 閒著循環 | 由裁判判和 | 第 3 次出現即和局 |
| 自然限著 | 依賽會規定（常見 60 回合無吃子） | 120 手無吃子即和局；將軍不另計 |
| 困斃 | 判負 | 相同 |

### 讓子

房主在房間設定選擇讓子種類與讓子方（紅方或黑方，代表棋力較強的一方）；開局時讓子方少掉下列棋子，其餘照常。「左」是讓子方自己看的左手邊：紅方為八路馬、九路車，黑方為 2 路馬、1 路車。

| 房規 | 讓子方少掉的棋子 |
| --- | --- |
| 不讓子（預設） | 無 |
| 讓單馬 | 左馬 |
| 讓雙馬 | 雙馬 |
| 讓單車 | 左車 |
| 讓九子 | 五兵、雙仕、雙相共九子，只留帥與車馬炮各二。依 1999 年許銀川讓九子對聶衛平的對局 |

民間讓子常附帶的「鐵兵」「出林車」等保護規則不採用。讓子設定記錄在對局中，回放與還原都從同一個讓子開局重建。

### 象棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內搜尋（每步 2 秒、深度上限 64 層）；沒有 worker 或搜尋失敗時改用同步版本（同一搜尋，限 150 毫秒） |

[bot 策略](../../server/src/bots/xiangqi-search.ts)（與西洋棋共用同一套搜尋架構）：

- 搜尋：迭代加深的主變例搜尋（PVS）加期望窗口、置換表（Zobrist 雜湊）、空著裁剪（只在還有車或兩個以上馬炮時使用，避免殘局「欠行」誤判）、後期走法縮減與裁剪、靜態交換評估（SEE）裁剪。走法排序：置換表走法、吃子（MVV-LVA，SEE 為負的排到最後）、殺手走法、反制走法、歷史分數。走出將軍時延伸一層。葉節點接靜態搜尋：吃子、被將軍時所有應將，第一層另外試不吃子的將軍。
- 評估（依車馬炮數量在中局與殘局權重間漸變）：子力、各兵種位置表、車馬炮機動性（蹩馬腿與塞象眼直接反映在步數）、缺仕相時對方車馬炮的威脅、九宮受攻、空頭炮與隔一子的炮、車的直線通路、士相全、連相、過河連兵、被捉與無根子；只剩不能過河的棋子時大幅打折。權重以自我對局的 Texel 法調校（[棋類評估調校](../development.md#棋類評估調校)）。
- 重複局面依本遊戲房規判斷：搜尋中回到上次吃子後出現過的同一局面（同一方走）時，若這段循環裡一方每步都將軍、另一方沒有，將軍方視為判負；其他循環（含長捉）視為和局。120 手無吃子為和局，困斃與將死同樣判負。
- 開局庫：中炮對屏風馬、反宮馬、順炮、列炮、仙人指路、飛相局、起馬局、過宮炮等主變（[`xiangqi-book.ts`](../../server/src/bots/xiangqi-book.ts)），依收錄次數加權隨機選；讓子開局不會命中。
- 根節點先套用規則判定：能立即取勝就走；會因長將判負的走法在還有其他走法時一律排除；會造成重複局面或無吃子和局的走法以和局計分。

強度實測（本機單執行緒，每手 2 秒）：開局與中局約 12–15 層、每秒 12–29 萬個節點；搜尋大多在預算的六成內收斂而提早落子。深度隨主機速度改變。

## 西洋棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。規則實作：[`chess.ts`](../../shared/src/rules/chess.ts)。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 8 × 8 深淺格，左上角（a8）為淺格；依視角旋轉，自己永遠在下方，棋子保持正立；下緣標示 a–h 檔，左緣標示 1–8 列。深淺格顏色取自棋盤外觀（淺格亮度 0.40–0.62、深格 0.10–0.22，兩者對比至少 1.6） |
| 棋子 | 王、后、車、象、馬、兵的原創 SVG 剪影；白方用棋子外觀的淺色棋子色、黑方用深色棋子色，各以另一色描邊，邊框與光澤沿用棋子外觀 |
| 先手與顏色 | 座位順序在前的玩家執白、先手 |
| 手數紀錄 | 兩種語言都使用標準代數記譜（見下方） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 無 |

1. 走法：王走一格；后直橫斜不限距離；車直橫、象斜走不限距離，中間不能有子；馬走 L 形並可跳過其他棋子；兵向前一格（從起始格出發可走兩格），斜前一格吃子。
2. 任何一步都不能讓自己的王處於被將軍的狀態；伺服器拒絕這類走法，牌桌也只顯示合法落點。解將的方法有三種：移開王、吃掉攻擊的棋子、擋住攻擊線；馬的攻擊無法擋住。
3. 王車易位：王向沒動過的車靠近兩格，車跳到王的另一側；兩子都沒動過、中間沒有棋子，王不能在被將軍時出發、不能經過或落在被攻擊的格子。
4. 吃過路兵：敵兵從起始格一次走兩格並停在己方兵旁邊時，己方兵只能在緊接著的下一步斜走到它跳過的格子吃掉它。
5. 升變：兵走到底線必須變成后、車、象或馬；牌桌以對話框讓玩家選擇，伺服器拒絕沒有指定升變棋子的走法。
6. 將死對方獲勝。以下情況由伺服器**自動**判和：困斃（輪到的一方沒被將軍但無合法步）、同一局面（棋子位置、輪到哪一方、王車易位權利與可實際吃過路兵的狀態相同）第 3 次出現、雙方各走 50 步（100 手）都沒有吃子或動兵，以及子力不足以將死（王對王、王加單象或單馬對王、雙方只剩同色格的象）。
7. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
8. 逾時由 bot 代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（將死、困斃、重複局面、五十步和局、子力不足、認輸、雙方同意和局）與手數（雙方合計）。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 和局與正式賽規的差異

| 項目 | 正式賽規 | 本遊戲 |
| --- | --- | --- |
| 三次重複、五十步 | 玩家須向裁判申請和局（五十步），或在第三次出現時申請 | 條件成立立即自動判和，不需宣告；沒有五次重複與七十五步的強制規則 |
| 子力不足 | 死局（無法將死）判和 | 只判死局中最常見的三種：王對王、王加單象或單馬對王、雙方只剩同色格的象；其他無法將死的局面照常下完 |
| 三次重複的比較 | 比較棋子位置、輪到誰、王車易位與吃過路兵的權利 | 相同；吃過路兵權利只在真有合法的吃法時才計入 |
| 計時 | 棋鐘，時間用完判負 | 平台的每手計時，逾時代走一步，不判負 |

### 記譜

標準代數記譜（SAN），英文棋子字母，兩種語言相同：K 王、Q 后、R 車、B 象、N 馬，兵不標字母。

| 項目 | 寫法 |
| --- | --- |
| 一般走法與吃子 | `e4`、`Nf3`、`Nxe5`；兵吃子寫出發的檔：`exd5` |
| 同類棋子都能走到同格 | 先補出發檔（`Nbd2`），檔相同再補列（`R1e2`），都相同才寫完整格名 |
| 吃過路兵 | 與一般兵吃子相同：`exd6` |
| 王車易位 | 短易位 `O-O`，長易位 `O-O-O` |
| 升變 | 目標格加 `=` 與新棋子：`e8=Q` |
| 將軍與將死 | 結尾加 `+` 或 `#` |

選好但尚未確認的走法（觸控的「待確認」）以同樣的記譜顯示；兵升變時棋子尚未選定，顯示為 `e8=?`。

### 西洋棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內搜尋（每步 2 秒、深度上限 64 層）；沒有 worker 或搜尋失敗時改用同步版本（同一搜尋，限 150 毫秒） |

[bot 策略](../../server/src/bots/chess-search.ts)（與象棋共用同一套搜尋架構）：

- 搜尋：迭代加深的主變例搜尋（PVS）加期望窗口、置換表（Zobrist 雜湊）、空著裁剪（只剩兵時不用，避免欠行局面）、後期走法縮減與裁剪、逆向無益裁剪、SEE 裁剪。走法排序：置換表走法、吃子（MVV-LVA，SEE 為負的排到最後）、升變、殺手走法、反制走法、歷史分數。走出將軍時延伸一層。葉節點接靜態搜尋：SEE 不虧的吃子與升后，被將軍時改搜所有應將。
- 評估（依子力在中局與殘局權重間漸變）：子力、各棋子位置表、機動性、兵形（疊兵、孤兵、並排兵、受保護兵）、通路兵（依前進程度、前方是否空、雙方王的距離）、車占開放線與第七列、雙象、馬象前哨、王前兵盾與開放線、王區受攻、被兵攻擊與無保護的棋子。無兵且優勢不到一車時大幅打折，異色象殘局減半；子力大幅領先時把對方王逼向邊角。權重目前是手設值：以自我對局的 Texel 法調校（[棋類評估調校](../development.md#棋類評估調校)）後在對戰場與手設值打平，因此未採用。
- 和局：搜尋中回到本路線出現過的局面，或本局之前已出現兩次的局面，以和局計分；半步數達 100 與子力不足也是和局。無合法步時，被將軍為負（越快將死分數越高），否則為和。
- 開局庫：開放性開局、西西里、法蘭西、卡羅－卡恩、后翼棄兵、印度防禦、英國式等常見開局的主變（[`chess-book.ts`](../../server/src/bots/chess-book.ts)），依收錄次數加權隨機選。
- 根節點先套用規則判定：能立即將死就走；會直接造成規則判和（含子力不足、三次重複、五十步）的走法以和局計分，領先時自然避開，落後時可當作求和的退路。

強度實測（本機單執行緒，每手 2 秒）：開局約 16 層，複雜中局（Kiwipete 局面）約 14 層，殘局 17 層以上，每秒 17–31 萬個節點；搜尋大多在預算的六成內收斂而提早落子。深度隨主機速度改變。

## 暗棋

台灣規則的象棋暗棋，2 人對局。蓋著的棋子身份只存在伺服器端。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（與黑白棋相同）；座位順序在前的玩家先手 |
| 棋盤 | 4×8 半盤，固定不旋轉，下方為 1 列、左方為 a 行（`banqiBoard()`） |
| 棋子 | 象棋 32 子全部洗牌後蓋著：紅方帥、仕、相、俥、傌、炮、兵，黑方將、士、象、車、馬、包、卒（每色 1 帥將、仕士／相象／俥車／傌馬／炮包各 2、5 兵卒）；洗牌使用注入的亂數（預設為密碼學亂數） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | **連吃與吃暗子**（`chain`，預設開啟）、**車衝**（`rookDash`，預設關閉）；等待中由房主設定，修改會清除準備狀態，開局後固定（[`BanqiOptions`](../../shared/src/games/banqi/types.ts)） |

1. 每回合只做一件事：翻開一顆蓋著的棋子（原地翻面，所有人都看得到）、把自己已翻開的棋子往上下左右走一格到空格，或吃子。
2. 翻開的第一顆棋子決定顏色：翻棋者執該棋子的顏色，對手執另一色。之後翻到任何顏色的棋子都只是翻棋。
3. 大小：帥將＞仕士＞相象＞俥車＞傌馬＞炮包＞兵卒。棋子可以吃相鄰、同級或較小的敵子；兵卒可以吃帥將，帥將不能吃兵卒。關閉連吃時，蓋著的棋子不能被吃。
4. 炮包不能吃相鄰的棋子；它隔著剛好一顆棋子（蓋著或翻開、任何顏色）沿橫線或直線跳過，吃掉遠處已翻開的敵子，距離與大小不拘。不吃子時走一格。
5. 連吃與吃暗子（房規，台灣常見規則）：
   - 吃子後，同一顆棋子可以在同一回合繼續吃子（只限吃子與吃暗子，翻棋與單純移動不行），隨時可以按「結束回合」停手。炮包的連吃是連續跳吃。
   - 吃暗子：翻開的棋子可以用吃子的走法攻擊蓋著的棋子（相鄰一格；炮包隔一子跳過；開啟車衝時為俥車線上第一顆棋子）。目標翻開後，若是攻擊方依大小規則吃得下的敵子（兵卒吃帥將、帥將不吃兵卒照舊；炮包翻出任何敵子都吃），就吃掉並移入，可繼續連吃；較大的敵子或自己顏色的棋子只翻開留在原位，攻擊方不動，回合結束。連吃中也可以吃暗子，失敗同樣結束回合。
   - 開局第一步一定是翻棋（還沒有翻開的棋子可以攻擊），顏色仍由第一次翻棋決定。
6. 車衝（房規）：俥車沿橫線或直線走任意格數（中間必須是空格），也可以隔著空格吃線上第一顆已翻開、且大小相等或較小的敵子；開啟連吃時，線上第一顆若是蓋著的棋子也可以隔空攻擊。這是台灣常見的「車像象棋的車一樣走」，不含炮式的跳吃。沒有這條房規時，俥車和其他棋子一樣只走一格。
7. 獲勝：吃光對手所有棋子（蓋著的也算），或讓對手在他的回合既無棋可翻、也無棋可走（只要場上還有蓋著的棋子，就一定有棋可翻）。
8. 連續 50 步沒有翻棋也沒有吃子即和局（雙方各走一步各算一步，連吃的吃子步使計數歸零；吃暗子不論成敗都歸零，失敗時視同翻棋）。
9. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
10. 逾時由 bot 代走；不會因超時判負。

結算顯示勝負、原因（棋子全被吃光、無子可動、無吃子和局、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 暗棋的隱藏資訊

| 對象 | 看得到 |
| --- | --- |
| 入座玩家（含 bot） | 公開盤面：蓋著的棋子都只是同樣的背面標記，翻開後才顯示身份。兩位玩家看到完全相同的盤面 |
| 未入座旁觀者 | 上帝視角：額外收到每顆蓋著棋子的身份（`observedPieces`），以淡色標在棋背上 |
| 手數紀錄、記譜、回放 | 紀錄只寫已翻開的棋子與被吃的棋子（翻棋記為 `翻 c3 俥`、走子 `俥 c3-c4`、吃子 `俥 c3xc4`、連吃前綴 `+`；吃暗子以 `?` 標示蓋著的目標，結尾是翻出的棋子：成功 `俥 c3x?c4 卒`、失敗 `俥 c3?c4 翻 傌`），不含任何仍蓋著的身份；吃暗子的身份在行動完成後才寫入。回放與錄製使用旁觀者視角，因此完成的對局可以看到所有棋子 |
| 持久化 | 洗牌結果（`hidden`）與公開盤面分開存放；還原時驗證 32 子的總和與公開紀錄一致 |

### 暗棋逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 單一強度。在 bot worker 內做迭代加深 expectimax（時間 1.8 秒、深度上限 16 層）；沒有 worker 或搜尋失敗時改用同步版本（3 層、固定節點上限） |

[bot 策略](../../server/src/bots/banqi-search.ts)（走法產生與雜湊在 [`banqi-position.ts`](../../server/src/bots/banqi-position.ts)，評估在 [`banqi-eval.ts`](../../server/src/bots/banqi-eval.ts)）：

- 只用自己的公開資訊。尚未看到的棋子 = 全部 32 子 − 盤面上已翻開的 − 紀錄中被吃的，它們就是翻棋與吃暗子這兩種機會節點的機率分布；對手以相同分布建模。吃暗子的每種結果依攻擊方吃不吃得下，分成吃掉移入或原地翻開。還沒決定顏色時隨機翻一顆。
- 連吃與車衝照房規精確展開：吃子後同一方再走一次，只能繼續吃子（含吃暗子）或停手，對手的連吃也算在內；吃暗子成功後的續吃多佔一層深度，避免連續吃暗子讓樹爆炸。走法產生器與共用規則 `bqMovesFrom` 逐格比對，任一房規組合都一致。
- 分數是 (−1, 1) 的勝率式尺度，機會節點的期望值即期望結果；贏棋略高於 1，越早贏越高。無吃子計數放在搜尋狀態：滿 50 步為和局（0 分），領先時避開、落後時追求；評估也隨計數往 0 衰減，鼓勵翻棋或吃子。
- 剪枝與排序：Zobrist 置換表（雜湊含蓋著的棋子分布與無吃子計數）、alpha-beta、機會節點的 star1 剪枝（尚未搜尋的結果以分數範圍估界，結果落在視窗外就停止）；走法依置換表最佳手、吃子（大吃小）、吃暗子（期望收穫）、翻棋（安全度）、history 排序。測試以無剪枝的完整 expectimax 對照，兩者的根節點分數一致。
- 翻棋候選：周遭相同的蓋著位置視為同一類，每類取一個，依「翻棋安全度」排序（翻出己方棋子被相鄰敵子吃掉的期望損失，翻出敵子威脅相鄰己子的期望損失）；根節點最多 8 個，往下依剩餘深度減為 3、2、1 個。吃暗子在根節點全列，往下依剩餘深度最多 3、2、1 個（連吃中最多 1 個，深度不足時不列）。
- 水平線以僅限吃子的靜止搜尋收尾（含連吃），不會把吃到一半的局面當成定局。
- 評估：雙方剩餘子力（翻開的加上蓋著的期望值）之差，除以場上總子力縮放後壓進 (−1, 1)。子力隨剩餘棋子調整：帥將、仕士、相象、俥車、傌馬在能吃它們的敵子減少時升值（敵方兵卒全滅且無帥將，帥就只怕炮）；兵卒在敵方帥將仍在時較高；炮包要有屏，隨場上子數遞減。場上 14 子以下時，加上「能吃對方、對方卻吃不了它」的追擊距離項，讓領先的一方會逼近而不是繞圈。
- 同步版本（回退）以淺層與固定節點上限搜尋，保持廉價。

## 跳棋

121 孔星形棋盤，每人 10 顆彈珠，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 2、3、4 或 6 個有人座位（人數彈性座位，可加開 P5、P6）；5 人時不能開始（[`playerCounts`](../../shared/src/games/chinesecheckers/definition.ts)） |
| 起始角 | 依人數固定（[`ccCorners`](../../shared/src/rules/chinesecheckers.ts)）：2 人對角；3 人隔一角（目標角都是空角）；4 人兩組對角，空下一組對角；6 人坐滿。座位順序（N、E、S、W、P5、P6）的第一位從下方的角出發並先走，之後順時針輪流 |
| 視角 | 每位玩家的角轉到下方；旁觀者預設看第一位的視角。座位依角的位置排在棋盤上方（對角）或左右 |
| 記譜 | 以第一位玩家視角的座標記錄（`m1-k3`），連跳列出每個落點；被堵住而跳過記為「跳過」，多人對局的認輸記為「認輸」 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 沒有可調整的房規 |

1. 每回合移動自己的一顆彈珠：走到相鄰的空位，或跳過相鄰的一顆彈珠（任何顏色）落到同一方向正後方的空位。跳躍可以在同一回合朝任意方向連續進行；走一步之後不能再跳，跳完也不能再走一步。彈珠不會被吃，可以經過或停在任何角。
2. 玩家點選彈珠後直接點最終落點；伺服器以 BFS 找出最短的合法跳躍路徑並驗證，記錄中保存途中落點。起點在跳躍途中視為空位，但不能回到起點。
3. 所有彈珠都被堵住的玩家自動跳過，牌桌顯示「無棋可走，跳過」。
4. **勝利**：目標角（自己起始角的對角）10 個孔都被占滿，且至少一顆是自己的彈珠。**防堵規則**：其餘孔都由自己的彈珠填滿時，留在目標角的對手彈珠視為已抵達。**任何人走完一步後都會檢查**：對手把彈珠走進你目標角的最後一個空孔時，你立即獲勝（同為「全部抵達對角」），不必等到自己再走一步；一步只填一個孔，所以一次最多一人完成。牌桌的「到位」在目標角完成後顯示 10/10。
5. **3 人以上**：第一位完成者出現即結束，只有他獲勝。其餘玩家依「尚差列數」排名（每顆彈珠到目標角尖端的列數總和，減去填滿目標角的 20），越少越前面，相同則並列；認輸者排最後，越晚認輸名次越前。
6. **認輸**：可隨時認輸。2 人時對手獲勝。3 人以上時，認輸者的彈珠離開棋盤、不再輪到他，其餘玩家繼續；若輪到他時認輸，回合交給下一位並重新計時；只剩一人時該玩家獲勝（原因「認輸」）。
7. **提和**：只限 2 人，規則同[棋類共通](common.md#棋類共通)；3 人以上沒有提和。
8. **回合上限**：輪到的玩家已走滿 150 回合（含跳過，[`CC_TURN_LIMIT`](../../shared/src/rules/chinesecheckers.ts)）時結束，原因「達到回合上限」；沒有任何玩家能走時以「無子可動」結束。兩者都由尚差列數最少者獲勝（並列共同獲勝），所有玩家相同則為和局。
9. 逾時由 bot 代走一步；不會因超時判負。

結算顯示勝負、原因（全部抵達對角、認輸、雙方同意和局、達到回合上限、無子可動）與手數；3 人以上另列名次。歷史、統計與每日任務中，並列第一算贏。

### 跳棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 在 bot worker 內迭代加深搜尋（時間上限 2 秒；2 人不設深度上限，3 人以上最多 8 層，通常遠少於時間上限就搜完）；沒有 worker 或搜尋失敗時改用同步版本（2 層、數千節點） |

bot 策略（[搜尋](../../server/src/bots/chinesecheckers-search.ts)）：

- PVS alpha-beta 加置換表，每層只展開排序最前的走法（根節點 24 步，內層 6–8 步）。2 人時與對手對弈；3 人時與目前最領先的對手對弈，4 人以上與下一個行動的座位對弈（它的回應最直接），其餘座位視為不動，所以更長的推演建立在不會出現的盤面上；與舊 bot 的對戰中，超過 8 層明顯變弱，因此 3 人以上設上限。
- 走法排序 = 自己的改善量＋這步讓下一步能走出的最佳改善（所以先鋪路、再連跳的安排不會被截掉）＋相鄰己方彈珠的增減；完成目標為最高分，把彈珠走進對手目標角的最後一個空孔會讓對手立即獲勝，視為必敗。
- 評估 = 每顆彈珠的成本（到目標角尖端的列數＋落後彈珠的平方懲罰＋偏離中線的距離）、每顆彈珠現在最大的一次跳躍（連跳起點）、彈珠相鄰的對數；雙方各算一次後取差。
- 離回合上限（`CC_TURN_LIMIT`）剩 4 回合內，評估改成結算用的單純列數，與依進度判勝負的規則一致。撤回自己上一步的走法略扣分；同分的走法以每個局面固定的隨機擾動區分。
- 權重存於 [`chinesecheckers-weights.ts`](../../server/src/bots/chinesecheckers-weights.ts)，由 [`scripts/chinesecheckers-tune`](../../scripts/chinesecheckers-tune/tune.ts)（自對弈 SPSA 與兩組權重對戰）與單人賽跑速度的比較選定。

## 陸戰棋

2 人對局，棋子身份隱藏，由伺服器擔任裁判（[規則程式碼](../../shared/src/rules/landbattle.ts)、[伺服器](../../server/src/managers/games/landbattle-game.ts)）。台灣各地規則略有差異，本遊戲採用以下常見規則。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（與黑白棋相同的座位規則） |
| 棋盤 | 5 × 12 個站點（[`junqiBoard()`](../../shared/src/rules/board/boards.ts)），每方 6 排；細線為公路，粗線為鐵路：每方的最前排與倒數第二排，以及左右兩路；前線只有左、中、右三路相通，另外兩路被山界擋住。每方 5 個行營、2 個大本營 |
| 先後與視角 | 座位順序在前的玩家執紅、布在下方並先走；每位玩家都看到己方在下方，旁觀者預設從紅方看 |
| 棋子 | 每方 25 枚：司令、軍長、師長 ×2、旅長 ×2、團長 ×2、營長 ×2、連長 ×3、排長 ×3、工兵 ×3、地雷 ×3、炸彈 ×2、軍旗 |
| 計時 | 布陣共用一個期限；走子沿用棋類預設（每手 60 秒加 300 秒時間庫），開戰時補滿 |
| 房規 | 沒有可調整的房規 |

**布陣**

1. 雙方同時布陣（沿用十三支的共同期限機制），期限為回合時間加時間庫，至少 60 秒（[`lbDeploySeconds`](../../shared/src/rules/landbattle.ts)）。行營一開始是空的，其餘 25 個站點各放一枚。
2. 限制：軍旗在大本營、地雷只在最後兩排、炸彈不在第一排。違反限制的布陣會被伺服器拒絕。
3. 介面提供 4 種預設陣型（均衡、強攻、堅守、右翼，軍旗都由 3 枚地雷圍住）與「自動」（隨機合法布陣，地雷多半圍在軍旗旁）；手機與桌機都是「點選兩個位置交換」，違反限制的交換會被拒絕並提示原因。
4. 確認後不能更改。對手確認後，其空白棋子會出現在對方半場（只表示已完成，看不到身份）。期限到時未確認的真人改用自動布陣，bot 用自己的布陣；雙方都完成後由紅方先走。

**走法**

- 沿公路或行營斜線走一格；或沿鐵路直線走任意距離，途中不能有棋子。工兵可以沿鐵路轉彎（取最短路線）。
- 不能越過或停在己方棋子上；遇到第一枚敵方棋子即停下攻擊。行營內的棋子不能被攻擊。
- 兩方大本營內的棋子（包括走進去的）、地雷與軍旗都不能移動。

**交戰**

| 進攻方對防守方 | 結果 |
| --- | --- |
| 軍階不同 | 大吃小 |
| 軍階相同 | 同歸於盡 |
| 任一方是炸彈 | 同歸於盡 |
| 防守方是地雷 | 工兵排除地雷並進駐；其他棋子陣亡、地雷留下；炸彈與地雷同歸於盡 |
| 防守方是軍旗 | 任何棋子都能奪旗（炸彈也算奪旗） |

- 裁判只公布「勝、負、同歸於盡」，手數紀錄只有座標與結果（例如 `c5xc6 勝`），不記軍階。
- 司令陣亡時，該方軍旗的位置公開給所有人（同一手兩位司令同歸於盡時兩方都公開）。

**勝負**

1. 奪下對方軍旗，或輪到對方時對方沒有任何合法走法，即獲勝。
2. 連續 60 手（雙方合計，[`LB_QUIET_LIMIT`](../../shared/src/rules/landbattle.ts)）沒有交戰則和局。
3. 開戰後可隨時認輸；提和規則同[棋類共通](common.md#棋類共通)。布陣期間牌桌不顯示提和與認輸，手機右欄留給布陣按鈕（伺服器仍接受布陣中的認輸）。
4. 逾時由 bot 走一步合法棋；不會因超時判負。

**可見度**

| 對象 | 看得到的身份 |
| --- | --- |
| 入座玩家 | 自己的棋子；司令陣亡後對方軍旗；對局結束後全部 |
| 未入座的旁觀者、回放 | 雙方所有棋子（上帝視角） |

- 對方棋子只以站點與布陣起點識別，排列順序依布陣位置，與身份無關；身份從不出現在玩家的狀態、手數紀錄、bot 的輸入或統計中（[過濾測試](../../server/tests/runtime/landbattle-game.test.ts)）。
- 名牌顯示紅／藍、剩餘棋子數與「軍旗已現」；狀態列顯示上一手的交戰結果。

### 陸戰棋逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 布陣逾時 | 真人改用自動布陣；bot 用自己的布陣 |
| 走子逾時 | 由 bot 代走（[搜尋與落子時間](common.md#bot)） |
| bot | 每次隨機產生不同布陣；走子在 bot worker 內搜尋（時間 2 秒），沒有 worker 或搜尋失敗時改用同步版本（同一搜尋，兩層、最多 8 個抽樣、60 毫秒） |

[布陣](../../server/src/bots/landbattle-deploy.ts)、[推論](../../server/src/bots/landbattle-knowledge.ts)、[抽樣](../../server/src/bots/landbattle-inference.ts)、[搜尋](../../server/src/bots/landbattle-search.ts)與[盤面](../../server/src/bots/landbattle-world.ts)：

- **只用自己的視角**：自己的布陣、公開的手數紀錄（含交戰結果）與已公開的軍旗。測試確認同一段公開歷史、不同的隱藏布陣會得到相同的決策。
- **布陣**：混合策略，不使用固定模板。軍旗隨機放在左或右大本營；約六成用 3 枚地雷圍住軍旗，其餘圍 2 枚、第三個位置放炸彈或強子，另一枚地雷放到另一個大本營旁當誘餌；另一個大本營放弱子。其餘棋子依位置偏好加上隨機雜訊逐一放置（強子偏前排與鐵路、炸彈偏中段、工兵偏鐵路與後方）。
- **硬限制**：對方每枚棋子先依布陣規則排除不可能的身份；動過的不是地雷或軍旗，沿鐵路轉彎的是工兵，每次交戰只保留能產生公布結果的身份（且不是軍旗），司令陣亡時鎖定該棋子與軍旗。
- **聯合抽樣**：身份從整體後驗抽出，而不是逐枚獨立抽：
  - 布陣先驗是混合模型：介面提供的 4 種預設陣型（含左右鏡像，並保留三成機率給被改過的位置），加上一張廣泛的合法布陣表（自動布陣與 bot 布陣的統計）。先依觀察到的限制估出各成分的後驗，再抽出成分。
  - 行為似然（一般玩家的通則，不針對特定玩家）：強子與炸彈較常主動進攻；走到已證明夠強的我方棋子旁卻不攻擊，較不像會輸給它的棋子；從這種棋子旁走開，較不像能贏它的棋子；從未移動的後方棋子較可能是地雷。
  - 在選定成分下以 Metropolis 交換兩枚棋子的身份，數量與所有限制始終成立。
- **搜尋**：每個抽樣世界中，對每一步做 3 層 alpha-beta 加交戰的靜止搜尋，取所有世界的平均；每 3、6、12、24、48 個世界淘汰較差的一半候選步。樹中雙方都不是全知的：我方只在抽樣邊際機率下預期損失有限時才交戰，對方則依它看得到的資訊（我方布陣規則、移動、轉彎，以及在該世界中它自己棋子的身份所推得的交戰結果）判斷，所以不會假設對方看穿我方的虛張聲勢。走到連續無交戰上限的一步以和局計分。
- **資訊價值**：排長、連長（營長減半）攻擊身份不確定的棋子時，依該棋子身份分布的熵加分；把棋子直接走回上一手的位置會小幅扣分。
- **評估**：子力、逼近對方軍旗、推進、行營、困在大本營的棋子、軍旗旁的守衛、可移動棋子太少（沒有走法即落敗），以及對方軍旗旁仍有地雷時工兵的額外價值；輪到的一方已有棋子貼著對方軍旗即視為奪旗。
- **速度**：盤面是 typed array，走子以 make／unmake 原地修改；時鐘每 512 個節點檢查一次，沒做完的世界不計入。
- **強度**：[測試](../../server/tests/runtime/landbattle-bot-strategy.test.ts)確認走法產生與規則一致、抽樣守住所有限制且真實布陣始終可能、決策不讀隱藏身份、時間預算與合法性。對戰場中對上舊版（固定陣型、單層搜尋），每步 300 毫秒時贏得約九成的獲勝座位，正式預算時 20 場全勝。差距主要來自辨識介面預設陣型（舊版 bot 也用預設陣型布陣）：拿掉預設陣型的先驗時，對上舊版沒有顯著差異。

### 陸戰棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 奪旗（可回放）、最快奪旗手數、終局最多存活棋子 |
| 紀錄 | 進攻獲勝、擊倒對方司令（以司令陣亡時公開軍旗判定，不讀取隱藏身份） |

## 海戰棋

2 人對局，艦隊位置隱藏，由伺服器判定每一發的結果（[規則程式碼](../../shared/src/rules/battleship.ts)、[伺服器](../../server/src/managers/games/battleship-game.ts)）。採 Hasbro 經典艦隊。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（與黑白棋相同的座位規則） |
| 海域 | 每人一片 10 × 10（[`battleshipBoard()`](../../shared/src/rules/board/boards.ts)，全部是水域格）；欄 A–J 由左而右，列 1–10 由上而下 |
| 艦隊 | 航空母艦 5、戰艦 4、巡洋艦 3、潛艇 3、驅逐艦 2 格，共 17 格 |
| 先後 | 座位順序在前的玩家先射擊 |
| 計時 | 擺放共用一個期限；射擊沿用棋類預設（每手 60 秒加 300 秒時間庫），開戰時補滿 |
| 房規 | 「船隻不可相鄰」（連斜角也不行）、「命中可再射」（命中或擊沉後同一人再射一發）；預設都關閉 |

**擺放**

1. 雙方同時擺放，期限與陸戰棋布陣相同：回合時間加時間庫，至少 60 秒（[`bsPlaceSeconds`](../../shared/src/rules/battleship.ts)）。
2. 船隻橫放或直放，必須在海域內、不能重疊；預設可以相鄰，開啟「船隻不可相鄰」時周圍 8 格都不能有其他船。違反規則的艦隊會被伺服器拒絕。
3. 介面：選船後點船首（最上或最左格）位置；點已擺好的船拿起，再點一次旋轉；另有「旋轉」、「隨機擺放」、「清除」。違反規則的擺法會被拒絕並說明原因（超出海域、重疊、相鄰）。
4. 確認後不能更改；對手完成時狀態列顯示「對手已完成擺放」，看不到位置。期限到時未確認的真人改用隨機擺放，bot 用自己的擺法；雙方都完成後開始射擊。

**射擊與勝負**

- 輪到自己時朝敵方海域射擊一格，同一格不能射兩次。結果公布為未中、命中，或擊沉某艘船（公開該船的格子）；命中不透露是哪一艘。
- 沒有「命中可再射」時雙方一人一發輪流；開啟時命中或擊沉後由同一人再射。
- 擊沉對方全部 5 艘船即獲勝（結束原因「艦隊全滅」）。沒有和局，因此不開放提和；可隨時認輸，擺放期間也可以（擺放期間牌桌不顯示認輸，手機右欄留給擺放按鈕）。
- 逾時由 bot 代射一發；不會因超時判負。
- 手數紀錄：「B7 未中」「B7 命中」「B7 擊沉 驅逐艦」（英文 `B7 miss`、`B7 hit`、`B7 sunk Destroyer`）。

**可見度**

| 對象 | 看得到的艦隊 |
| --- | --- |
| 入座玩家 | 自己的艦隊、雙方的射擊結果、已擊沉的對方船隻；對局結束後全部 |
| 未入座的旁觀者、回放 | 雙方艦隊（上帝視角） |

- 對方艦隊從不出現在玩家的狀態、手數紀錄、bot 的輸入或統計中；手數紀錄只有座標、結果與擊沉的船名及格子（[過濾測試](../../server/tests/runtime/battleship-game.test.ts)）。
- 介面：電腦版敵方海域與我方海域並列；手機橫向以敵方海域為主，右側小圖顯示另一片海域，點小圖互換。名牌顯示剩餘船數。

### 海戰棋逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 擺放逾時 | 真人改用隨機擺放；bot 用自己的擺法 |
| 射擊逾時 | 由 bot 代射一發（[搜尋與落子時間](common.md#bot)） |
| bot | 擺放用混合策略；射擊在 bot worker 內抽樣整支對手艦隊（預算 1 秒），打在最可能有船的格子；沒有 worker 或搜尋失敗時改用同步的機率密度 |

- **擺放**（[程式碼](../../server/src/bots/battleship-fleet.ts)）：從 240 個隨機合法艦隊中依權重抽出一個。權重偏好船格靠近邊緣（每局的偏好強度在 0 到上限之間隨機抽，沒有固定風格）與船隻彼此相鄰：假設所有合法艦隊機率相同的射手最先打中央，邊緣的船較晚被找到；相鄰的船被打中後看起來像一艘長船，要多花射擊才能分開。量測（只看射手需要的射擊數）：射手面對完全隨機的艦隊約 45 發，面對這種擺法約 47–48 發（機率密度與抽樣兩種射手相同）。
- **射擊**（[搜尋](../../server/src/bots/battleship-search.ts)）只讀自己的射擊結果：依未中、已擊沉的船（不可相鄰時連同周圍）與沒有被擊沉解釋的命中，抽出最多 8,000 支完整的對手艦隊。每支艦隊先讓每個命中各自被一艘船覆蓋，再把其餘船隻放進任何放得下的位置，並以選擇數加權，使每支符合所有觀察的艦隊機率相同。射向有船艦隊占比最高的格子，並列時隨機；命中時自然會打鄰格。抽不到足夠艦隊時（例如命中位置自相矛盾）改用機率密度。抽樣不假設對手的擺放習慣：偏好邊緣或相鄰的先驗在對手隨機擺放時會多花 3–5 發，猜錯比不猜更貴，也不學習特定玩家。
- 同步版本（回退）：每一步只需數千次擺法檢查的機率密度——依剩餘船隻計算每格被覆蓋的擺法數；有未擊沉的命中時只計經過命中的擺法並大幅加權（目標模式），否則棋盤格同色格優先（搜尋模式）。
- 強度：[測試](../../server/tests/runtime/battleship-bot-strategy.test.ts)確認擺放合法、抽樣機率與觀察一致，以及整局平均擊沉艦隊的射擊數；對戰場中對上只做機率密度、擺放分散的舊版 bot，勝率約 60%。

### 海戰棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 全殲敵艦隊（可回放）、最少射擊獲勝、擊沉敵艦 |
| 指標 | 命中率（命中數／射擊數） |

## 密碼推理

2–6 人同時破解同一組密碼，大廳歸在棋類（[規則程式碼](../../shared/src/rules/codebreaker.ts)、[伺服器](../../server/src/managers/games/codebreaker-game.ts)）。名稱避開既有商標，玩法是常見的 1A2B／顏色密碼。

| 設定 | 規則 |
| --- | --- |
| 人數 | 2–6 個有人座位，座位彈性（可加開 P5、P6），bot 可補位；沒有認輸與提和 |
| 密碼 | 每局由伺服器用作業系統亂數抽出**一組**，全桌猜同一組；每局重抽，不由房間代碼、對局 ID 或任何客戶端看得到的資料推得 |
| 房規「密碼種類」 | 數字（預設，1A2B）：4 個**不重複**的數字 0–9。顏色：4 格、6 種顏色（各有不同形狀），可重複 |
| 回應 | 數字 `nAmB`：A 是數字對且位置對，B 是數字對但位置不對。顏色：實心＝顏色與位置都對、空心圈＝顏色對但位置不對（重複的顏色不會多算） |
| 猜測上限 | 每人 10 次 |
| 計時 | 每輪共用一個期限：回合時間加時間庫，至少 20 秒（[`cbRoundSeconds`](../../shared/src/rules/codebreaker.ts)；預設房間計時 60 秒、時間庫 0） |

**回合**

1. 同步進行。每位尚未猜中、也未用完 10 次的玩家，每輪各送出一次猜測；猜測在本輪結算前保留在伺服器，只有送出者自己看得到。
2. 全部送出，或期限到，就結算：依座位順序為每個猜測算出回應，開始下一輪。期限到時，還沒送出的真人由 bot 代猜（歷史標示「代猜」）；bot 不等期限，逐一送出。
3. 猜測必須格式正確（數字模式 4 個不重複的數字），但不必符合先前的回應。每輪一次，沒有連續送出的空間。
4. 猜中的玩家不再被詢問，其他人繼續；所有人都猜中或用完 10 次時結束。

**勝負**

- 猜中者依次數排名，次數最少者獲勝；次數相同者並列獲勝與名次。沒猜中的人並列最後（名次在所有猜中者之後）。沒有人猜中就沒有贏家（全員記為落敗）。
- 對局沒有結果（中止、未完成）時不給任何獎勵，沿用平台既有規則；每日任務「完成 2 局密碼推理」只算完成的對局。

**可見度**

| 對象 | 看得到 |
| --- | --- |
| 入座玩家 | 自己的猜測與回應、自己已送出但尚未結算的猜測；其他座位只有已猜次數、是否猜中、本輪是否已送出。答案在結束前不傳送 |
| 未入座的旁觀者、回放 | 答案與所有人的猜測（上帝視角） |
| 對局結束後 | 所有人：答案與每位玩家的完整猜測紀錄 |

- 公開的 `log` 只有「誰在第幾輪猜過、是否猜中」，沒有猜測內容；答案與他人猜測從不出現在玩家的狀態、`log`、呈現畫格、bot 的輸入或統計中（[過濾測試](../../server/tests/runtime/codebreaker-game.test.ts)）。回放錄下的是旁觀者視角，只有結束後的回放可看。
- 介面：桌機上方是其他座位（猜測次數、猜中、已送出），中間左側是目前觀看座位的猜測歷史，右側是輸入欄（4 格、數字鍵盤或 6 個彩色形狀、刪除、清除、送出）與自己的座位；桌機鍵盤可直接輸入數字（顏色用 1–6）、Backspace、Enter。手機橫向（706×336）分成座位、歷史、輸入三欄。結束時顯示答案、名次表，並可展開每位玩家的猜測。

### 密碼推理逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 由 bot 代猜（歷史標示「代猜」） |
| bot | 維護符合自己回應的候選集合，以最少期望猜測次數為目標：第一手固定開局（數字 0123、顏色 AABB，符號隨機重新標號），第二至第六手查離線算好的對照表，其餘由精確搜尋決定 |

- [策略](../../server/src/bots/codebreaker-strategy.ts)只讀自己的回應（`histories` 只含自己）；每次決策數毫秒，在事件迴圈上同步執行，不使用 worker pool。
- **對照表**（[`codebreaker-openings.ts`](../../server/src/bots/codebreaker-openings.ts)）：每一步的最佳猜法只取決於至今的回應，所以離線對每個可能的答案各打一遍，選出總猜測數最少的猜法，路徑為回應序列（`exact × 5 + partial`，以點相接）。由 [`scripts/codebreaker-openings.ts`](../../scripts/codebreaker-openings.ts) 產生；改動搜尋或估計曲線後重新執行（`npx tsx --tsconfig server/tsconfig.json scripts/codebreaker-openings.ts --write`；`--report` 只印出對所有答案的平均）。候選在數十個以內的節點由完整搜尋求解（腳本的 `--exact-plan`）；偏離對照表（例如逾時由別的 bot 代猜）時才即時搜尋。
- **精確搜尋**（[求解器](../../server/src/bots/codebreaker-solver.ts)）：全部 5,040（數字）或 1,296（顏色）組碼都是可選的猜法，回應用兩次查表算出。候選 ≤ 8 個時對每個猜法遞迴求精確的期望猜測次數（下界剪枝）；更多時用「剩餘候選的預期猜測數」曲線估價，必要時再前瞻一層。猜測可以是非候選的探測碼。
- 別人的進度不影響選擇：每輪所有未猜中的座位同時猜一次，所以看到別人猜中時，自己已經用掉同樣的次數而不可能再贏或並列；最小化期望猜測次數就是最好的打法。
- 強度：對全部可能的答案平均 5.226 次（數字，理論最佳 5.213，最長 7 次）與 4.400 次（顏色，最佳 4.340，最長 6 次），舊版 bot 在隨機答案上約 5.26 與 4.45。已接近上限：對戰場中新舊版同局的勝負差異不顯著，同一組答案上新版較快的次數多約 16%（[測試](../../server/tests/runtime/codebreaker-bot-strategy.test.ts)）。

### 密碼推理統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 猜中密碼（可回放）、最少猜測次數 |
| 指標 | 猜中時平均猜測次數；場數與勝場為共通項目 |
