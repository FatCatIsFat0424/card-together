# 棋類遊戲

各棋類的規則。認輸、提和、計時、視角與手數紀錄：[棋類共通](common.md#棋類共通)；介面：[棋盤牌桌](../interface.md#棋盤牌桌)。

## 黑白棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 8×8，固定不旋轉，下方為 1 列、左方為 a 行；手數以座標記錄（`d3`），無子可下記為「跳過」 |
| 開局 | d4、e5 為白，e4、d5 為黑；座位順序在前的玩家（N、E、S、W 之順）執黑先手 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 沒有可調整的房規 |

1. 每步下在空格，並在至少一個方向（橫、直、斜）上夾住連續的對手棋子，其中必須至少夾住一子；被夾住的棋子全部翻成己色。同時夾住多個方向時一併翻轉。
2. 沒有合法位置的玩家自動跳過，由對手繼續下；伺服器在對手落子後立即記錄跳過，牌桌顯示「無子可下，跳過」，直到下一手為止。
3. 雙方都無子可下時結束（通常是棋盤下滿，也可能提早）。棋子較多者獲勝，數量相同為和局。
4. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
5. 逾時由伺服器依簡單難度的規則代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（子數較多、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同：翻最多子的合法位置，加上少量隨機 |
| 簡單 | 貪心：選翻子最多的位置，並加入少量隨機，偶爾下較差的一步；同步執行 |
| 困難 | 在 bot worker 內迭代加深的 alpha-beta（時間 1 秒、深度上限 10 層）；沒有 worker 或搜尋失敗時以簡單難度代走 |

[困難策略](../../server/src/bots/reversi-search.ts)：

- 評估 = 位置權重（角落高、角落旁的 X／C 位置低；角落被佔後不再扣分）＋行動力差＋接近終局時的子數差；終局以子數差精確計算，勝負優先於啟發式分數。
- 沒有合法步時視為跳過，不消耗深度；雙方都不能下則是終局。
- 搜尋依位置權重排序以加快剪枝，分數相同的走法隨機挑選；只使用盤面這份公開資訊。
- 同步的困難策略（只服務其他座位的自動動作）以淺層（3 層）搜尋，保持廉價。

### 黑白棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 終局最多棋子、全滅對手（可回放） |
| 紀錄 | 佔據角落、單步最多翻子 |

## 鬥獸棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 7×9，雙方半場各有一條河（2×3 兩塊水域）、三個陷阱與一個獸穴；依視角旋轉，自己永遠在下方，棋子文字保持正立；座標以先手視角標示（左下 a1、右上 g9） |
| 棋子 | 每方 8 隻：象 8＞獅 7＞虎 6＞豹 5＞狼 4＞狗 3＞貓 2＞鼠 1；開局為點對稱的標準排法，棋子上標示動物與等級數字 |
| 先手與顏色 | 座位順序在前的玩家執紅、先手、從下方出發；另一方執藍 |
| 手數紀錄 | 動物加座標（`象g3-g4`；吃子為 `象g3xg4`；英文用兩字母縮寫，如 `El g3xg4`） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 沒有可調整的房規 |

1. 每步走一隻棋子，上下左右一格；不能走到有自己棋子的格子，也不能走進自己的獸穴。
2. 等級相同或較低的棋子可以吃；例外是鼠可以吃象，象不能吃鼠。
3. 只有鼠可以進入河中（水域）。**河中與岸上不能互吃**：河中的鼠不能吃岸上的棋子（包括象），岸上的棋子（包括鼠）也不能吃河中的鼠，鼠不能以吃子的方式離開水域；兩隻同在河中的鼠可以互吃，鼠可以走到空的岸上格。
4. 獅、虎可以沿直線跳過河（橫向跳過 2 格水域、縱向跳過 3 格水域），落點為空格或可吃的敵子；跳越的水域中只要有任何一隻鼠（不論敵我）就不能跳。
5. 棋子在對方陷阱內時等級視為 0：任何棋子都能吃它（象也能吃陷阱內的鼠），它自己吃不了任何棋子（陷阱內的鼠也不能吃象）；離開陷阱即恢復原等級。自己的陷阱對自己沒有影響。
6. 勝負：走進對方獸穴者勝；吃光對方所有棋子者勝；走完後對方沒有任何合法步者勝。
7. 和局：連續 100 手（雙方各 50 手）沒有吃子，判「無吃子和局」。不另設重複局面規則。
8. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
9. 逾時由伺服器依簡單難度的規則代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（進入獸穴、棋子全被吃光、無子可動、無吃子和局、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 鬥獸棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同：能進穴就進穴，否則偏好吃大子、其次向對方獸穴靠近，加上隨機 |
| 簡單 | 只看一步：進穴＞吃子（等級越高越優先）＞向獸穴靠近，並加入較大的隨機，常忽略威脅；同步執行 |
| 困難 | 在 bot worker 內迭代加深的 alpha-beta（時間 1 秒、深度上限 12 層，開局約可算 5 層）；沒有 worker 或搜尋失敗時以簡單難度代走 |

[困難策略](../../server/src/bots/jungle-search.ts)：

- 評估 = 子力價值（鼠 300、貓 200、狗 250、狼 320、豹 420、虎 600、獅 700、象 800；陷阱內的棋子只算 30%）＋每前進一步向對方獸穴的加分＋距離獸穴 2 步以內的額外加分。
- 進入獸穴為勝，無合法步為負，兩者都依手數遞減，使搜尋偏好最快的勝利與最慢的失敗。
- 葉節點接 3 層只含吃子與進穴的靜態搜尋，避免在吃子中途停下；走法依進穴、吃子價值、前進量排序，分數相同的走法隨機挑選。
- 只使用盤面這份公開資訊，也不處理重複局面；同步的困難策略（只服務其他座位的自動動作）以淺層（3 層）搜尋，保持廉價。

### 鬥獸棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 進入獸穴獲勝（可回放） |
| 紀錄 | 單局最多吃子、以鼠吃象、跳河次數 |

## 五子棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 15×15 交叉點（[棋盤](../../shared/src/rules/board/boards.ts)），固定不旋轉，下方為 1 列、左方為 a 行；手數以座標記錄（`h8`） |
| 先手 | 座位順序在前的玩家執黑先手，之後輪流落子 |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 連珠禁手（預設關）、交換開局（預設關）；兩項都會讓準備狀態失效，開局後不能更改 |

1. 每手下一子在空的交叉點，下了不能移動或收回。
2. 預設為無禁手：橫、直、斜任一方向連成五子或更多（長連也算）即獲勝，黑白皆然。
3. 棋盤下滿仍無人連成五子為和局。
4. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
5. 逾時由伺服器依簡單難度的規則代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（連成五子、棋盤下滿、認輸、雙方同意和局）與子數；獲勝的五子在盤面上加框。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 房規

| 房規 | 內容 |
| --- | --- |
| 連珠禁手 | 只限制黑棋：長連（六子以上）、雙四、雙三的位置不能下，伺服器直接拒絕，牌桌上輪到黑棋時以紅叉標示。黑棋必須恰好連成五子才算贏，白棋五子以上都算贏。下出恰好五子的位置永遠合法，即使同時形成雙三、雙四或長連 |
| 交換開局 | 採標準「交換」（swap）：先手玩家依序下黑、白、黑三顆開局子，後手玩家再選顏色。選執黑代表與先手交換，選執白則維持原樣；之後由白棋先下。座位順序不變，只有顏色互換，結算會記錄誰執黑 |

禁手判定（[規則](../../shared/src/rules/gomoku.ts)）：

- 四：下這一子後，再一子就能連成恰好五子的棋型；一排「活四」（兩端都能成五）只算一個四，同一排兩處獨立的缺口則算兩個四。
- 三：再一子就能變成活四的棋型，且那個活四的落點本身必須合法（不是長連、雙四或雙三）；有一端被擋住的三、貼著邊界無法延伸的三都不算活三。
- 雙四與雙三不論是否同一子造成都禁止；四三（一個四加一個活三）合法。長連加上另一個方向的恰好五子，視為五子獲勝。
- 若黑棋輪到時所有空點都是禁手（只可能發生在幾乎下滿的棋盤），視為棋盤下滿的和局。

交換開局期間，輪到的玩家可以認輸或提和；逾時時，先手玩家由簡單難度代下開局子，後手玩家由簡單難度代為選色。

### 五子棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同：依棋型分數選點，加上少量隨機 |
| 簡單 | 棋盤空時下天元；有一手能連成五子就一定下；否則在已有棋子兩格內的空點依棋型分數（自己的連線加上堵住對手的連線）加隨機係數挑選，約 18% 的機會從前幾名中亂選，因此偶爾漏堵；同步執行。連珠禁手開啟時不下禁手點。交換開局時依三顆開局子的形勢加雜訊決定是否執黑 |
| 困難 | 在 bot worker 內迭代加深的 alpha-beta（時間 1 秒、深度上限 10 層）；沒有 worker 或搜尋失敗時以簡單難度代走 |

[困難策略](../../server/src/bots/gomoku-search.ts)：

- 棋型分數 = 把棋盤切成所有長度 5 的視窗，視窗裡只有一方的棋子時，依棋子數（1／2／3／4）給予遞增分數，雙方都有則不計分；落子時只更新涉及的視窗，所以每一手只要幾十次更新。
- 每個節點先檢查威脅：自己能連成五子就是必勝；對手有兩個不同的成五點就是必敗；只有一個就只考慮堵住它（禁手的黑棋堵不了也是敗）。強制回應不消耗深度（最多延伸 24 層），因此連續的四可以讀到底。
- 其餘節點只考慮已有棋子兩格內、依棋型分數排序後的前幾手（根 16、之後逐層縮減：10、8、6、5、4）；黑棋在連珠禁手下略過禁手點。
- 迭代加深，每層搜完才採用結果；分數相同的走法隨機挑選，已分出勝負就提早結束。只使用盤面這份公開資訊。
- 同步的困難策略（只服務其他座位的自動動作）使用相同搜尋，但限制深度 4 層與 2,500 個節點，保持廉價。
- 交換開局選色：困難難度搜尋白棋在此局面下的形勢，白棋較差就執黑。

### 五子棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 連五獲勝（可回放）、獲勝最少子數、最長棋局（子數）、連珠禁手勝場 |

## 象棋

2 人對局，沒有隱藏資訊，所有座位與旁觀者看到相同的盤面。規則實作：[`xiangqi.ts`](../../shared/src/rules/xiangqi.ts)。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（人數彈性座位，上限 2）；「補 bot」補到 2 人為止 |
| 棋盤 | 9 路 × 10 線交叉點，楚河漢界與雙方九宮；依視角旋轉，自己永遠在下方，棋子文字保持正立；下緣標示自己這一方的路數（紅方一～九、黑方 1～9，各自從右數起） |
| 棋子 | 紅：帥、仕、相、俥、傌、炮、兵；黑：將、士、象、車、馬、包、卒 |
| 先手與顏色 | 座位順序在前的玩家執紅、先手；有讓子時仍由紅方先走 |
| 手數紀錄 | 繁體中文用中文記譜，英文用 WXF 記譜（見下方） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | 讓子（見下方），預設不讓子 |

1. 走法：帥（將）、仕（士）只在九宮內走，帥直橫一步、仕斜一步；相（象）斜走兩步，中間有子（塞象眼）不能走，不能過河；傌（馬）先直橫一步再斜一步，第一步有子（蹩馬腳）不能走；俥（車）直橫不限距離；炮（包）移動同車，吃子必須隔恰好一子；兵（卒）向前一步，過河後也可以橫走一步，不能後退。
2. 雙方將帥不能在同一路上直接相對（中間沒有棋子），任何一步都不能讓自己的將帥處於被將軍的狀態；伺服器拒絕這類走法，牌桌也只顯示合法落點。
3. 將死對方獲勝；輪到的一方沒有合法步時，即使沒被將軍也判負（困斃）。
4. 長將判負：同一局面（含輪到哪一方）第 3 次出現時，若某一方從該局面第一次出現起的每一步都在將軍，該方判負；雙方都一直將軍，或沒有任何一方一直將軍，判「重複局面」和局。
5. 雙方共 120 手（各 60 步）沒有吃子，判「無吃子和局」。
6. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
7. 逾時由伺服器依簡單難度的規則代走一步合法棋；不會因超時判負。

結算顯示勝負、原因（將死、困斃、長將判負、重複局面、無吃子和局、認輸、雙方同意和局）與手數（雙方合計）。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 與正式賽規的差異

亞洲象棋聯合會與中國象棋協會的正式規則對重複局面有細緻的裁決，本遊戲採簡化規則，由伺服器自動判定：

| 項目 | 正式賽規 | 本遊戲 |
| --- | --- | --- |
| 長將 | 單方長將判負 | 相同：第 3 次出現同一局面時，期間每一步都將軍的一方判負 |
| 長捉（反覆捉子）、一將一捉等 | 依「禁止著法」判負或變著 | 不判；只要不是單方長將就以重複局面和局 |
| 雙方都違規或都不違規 | 依細則判和或要求變著 | 一律和局 |
| 閒著循環 | 由裁判判和 | 第 3 次出現即和局 |
| 自然限著 | 依賽會規定（常見 60 回合無吃子） | 120 手無吃子即和局；將軍不另計 |
| 困斃 | 判負 | 相同 |

### 讓子

房主在房間設定選擇讓子種類與讓子方（紅方或黑方，代表棋力較強的一方）；開局時讓子方少掉下列棋子，其餘照常。「左」是讓子方自己看的左手邊：紅方為八路馬、九路車，黑方為 2 路馬、1 路車。

| 房規 | 讓子方少掉的棋子 |
| --- | --- |
| 不讓子（預設） | 無 |
| 讓單馬 | 左馬 |
| 讓雙馬 | 雙馬 |
| 讓單車 | 左車 |
| 讓九子 | 五兵、雙仕、雙相共九子，只留帥與車馬炮各二。依 1999 年許銀川讓九子對聶衛平的對局 |

民間讓子常附帶的「鐵兵」「出林車」等保護規則不採用。讓子設定記錄在對局中，回放與還原都從同一個讓子開局重建。

### 記譜

| 項目 | 中文（`zh-TW`） | WXF（`en`） |
| --- | --- | --- |
| 基本格式 | 棋子＋所在路數＋進／退／平＋目標 | 字母＋路數＋`+`／`-`／`=`＋目標，如 `C2=5` |
| 路數 | 紅方中文數字（一～九），黑方阿拉伯數字（1～9），各自從右數起 | 雙方都用阿拉伯數字 |
| 目標 | 平：目標路數；直走的帥、俥、炮、兵進退寫步數；斜走的仕、相、傌進退寫目標路數 | 相同 |
| 同一路兩個相同棋子 | 前／後取代路數：`前俥平五`、`後馬退4` | `+`／`-` 取代路數：`R+=5`、`H--4` |
| 同一路三個兵 | 前／中／後：`中兵平六` | 由前往後編號取代字母：`25=6` |
| 同一路四、五個兵 | 一兵～五兵（由前往後）：`二兵平六` | 同上 |
| 兩路各有兩個以上的兵 | 前／中／後加上路數：`前兵五平四` | 編號加路數：`15=4` |

字母：K 帥將、A 仕士、E 相象、H 傌馬、R 俥車、C 炮包、P 兵卒。

### 象棋的逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同 |
| 簡單 | 看兩手：每一步以對手最好的回應後的靜態評估計分，加上約 1.5 個兵的隨機；能一步取勝一定走；同步執行 |
| 困難 | 在 bot worker 內迭代加深的 alpha-beta（時間 1.5 秒、深度上限 12 層，開局約可算 5 層）；沒有 worker 或搜尋失敗時以簡單難度代走 |

[困難策略](../../server/src/bots/xiangqi-search.ts)：

- 評估 = 子力（俥 900、炮 450、傌 400、仕相 200、兵 100，過河後 180 以上並依接近九宮加分）＋位置（傌居中與前進、炮居中路、兵過河等）。
- 走法排序：吃子依「最有價值的被吃子、最便宜的攻擊子」（MVV-LVA），再來是殺手走法（killer moves）；被將軍時延伸一層；葉節點接只含吃子的靜態搜尋。
- 無合法步（將死或困斃）為負，依手數遞減；搜尋中回到本局或本路線已出現過的局面視為和局。
- 根節點先套用規則判定：能立即取勝就走；會因長將判負的走法在還有其他走法時一律排除（簡單難度也一樣）；會造成重複局面或無吃子和局的走法以和局計分。
- 同步的困難策略（只服務其他座位的自動動作）限 3 層、150 毫秒，保持廉價。

| 類型 | 項目 |
| --- | --- |
| 結果 | 將死對手（可回放）、最快將死步數（自己的步數） |
| 紀錄 | 將軍次數、單場最多吃子 |

## 暗棋

台灣規則的象棋暗棋，2 人對局。蓋著的棋子身份只存在伺服器端。

| 設定 | 規則 |
| --- | --- |
| 人數 | 恰好 2 個有人座位（與黑白棋相同）；座位順序在前的玩家先手 |
| 棋盤 | 4×8 半盤，固定不旋轉，下方為 1 列、左方為 a 行（`banqiBoard()`） |
| 棋子 | 象棋 32 子全部洗牌後蓋著：紅方帥、仕、相、俥、傌、炮、兵，黑方將、士、象、車、馬、包、卒（每色 1 帥將、仕士／相象／俥車／傌馬／炮包各 2、5 兵卒）；洗牌使用注入的亂數（預設為密碼學亂數） |
| 計時 | 棋類預設：每手 60 秒加 300 秒時間庫 |
| 房規 | **連吃**、**車衝**，預設都關閉；等待中由房主設定，修改會清除準備狀態，開局後固定 |

1. 每回合只做一件事：翻開一顆蓋著的棋子（原地翻面，所有人都看得到）、把自己已翻開的棋子往上下左右走一格到空格，或吃子。
2. 翻開的第一顆棋子決定顏色：翻棋者執該棋子的顏色，對手執另一色。之後翻到任何顏色的棋子都只是翻棋。
3. 大小：帥將＞仕士＞相象＞俥車＞傌馬＞炮包＞兵卒。棋子可以吃相鄰、同級或較小的敵子；兵卒可以吃帥將，帥將不能吃兵卒。蓋著的棋子不能被吃。
4. 炮包不能吃相鄰的棋子；它隔著剛好一顆棋子（蓋著或翻開、任何顏色）沿橫線或直線跳過，吃掉遠處已翻開的敵子，距離與大小不拘。不吃子時走一格。
5. 連吃（房規）：吃子後，同一顆棋子可以在同一回合繼續吃子（只限吃子，翻棋與單純移動不行），隨時可以按「結束回合」停手。炮包的連吃是連續跳吃。
6. 車衝（房規）：俥車沿橫線或直線走任意格數（中間必須是空格），也可以隔著空格吃線上第一顆已翻開、且大小相等或較小的敵子；這是台灣常見的「車像象棋的車一樣走」，不含炮式的跳吃。沒有這條房規時，俥車和其他棋子一樣只走一格。
7. 獲勝：吃光對手所有棋子（蓋著的也算），或讓對手在他的回合既無棋可翻、也無棋可走（只要場上還有蓋著的棋子，就一定有棋可翻）。
8. 連續 50 步沒有翻棋也沒有吃子即和局（雙方各走一步各算一步，連吃的吃子步使計數歸零）。
9. 可隨時認輸。輪到自己時可以提和，對手同意即和局，對手走子視為拒絕，被拒後需再走 3 手才能再提。
10. 逾時由伺服器依簡單難度的規則代走；不會因超時判負。

結算顯示勝負、原因（棋子全被吃光、無子可動、無吃子和局、認輸、雙方同意和局）與手數。歷史、統計與每日任務中，和局視為雙方同列第一（平手第一算贏）。

### 暗棋的隱藏資訊

| 對象 | 看得到 |
| --- | --- |
| 入座玩家（含 bot） | 公開盤面：蓋著的棋子都只是同樣的背面標記，翻開後才顯示身份。兩位玩家看到完全相同的盤面 |
| 未入座旁觀者 | 上帝視角：額外收到每顆蓋著棋子的身份（`observedPieces`），以淡色標在棋背上 |
| 手數紀錄、記譜、回放 | 紀錄只寫已翻開的棋子與被吃的棋子（翻棋記為 `翻 c3 俥`、走子 `俥 c3-c4`、吃子 `俥 c3xc4`、連吃前綴 `+`），不含任何仍蓋著的身份。回放與錄製使用旁觀者視角，因此完成的對局可以看到所有棋子 |
| 持久化 | 洗牌結果（`hidden`）與公開盤面分開存放；還原時驗證 32 子的總和與公開紀錄一致 |

### 暗棋逾時與 bot

| 項目 | 規則 |
| --- | --- |
| 逾時 | 與簡單難度相同 |
| 簡單 | 有「安全」的吃子（吃完後對方已翻開的棋子都吃不到它）就吃最有價值的；沒有就在翻棋與不吃子的走法中隨機選一個，連吃中則停手；同步執行 |
| 困難 | 在 bot worker 內做 expectimax（時間 1 秒、深度上限 6 層）；沒有 worker 或搜尋失敗時以簡單難度代走 |

[困難策略](../../server/src/bots/banqi-search.ts)：

- 只用自己的公開資訊。尚未看到的棋子 = 全部 32 子 − 盤面上已翻開的 − 紀錄中被吃的，它們就是翻棋這個機會節點的機率分布；對手以相同分布建模。
- 評估 = 雙方剩餘子力（翻開的加上蓋著的期望值）之差，再加上輪到的一方已經能吃到的最大子力；子力：帥將 100、仕士 60、相象 40、俥車 30、炮包 35、傌馬 20、兵卒 12。
- 翻棋只考慮鄰接棋子最多的 4 個蓋著位置（其餘位置彼此相近），每個位置對每種尚未出現的棋子加權平均。
- 還沒決定顏色時隨機翻一顆。
- 同步的困難策略（只服務其他座位的自動動作）以淺層（2 層）與固定節點上限搜尋，保持廉價。

### 暗棋統計

| 類型 | 項目 |
| --- | --- |
| 結果 | 終局剩餘最多棋子、吃光對手（可回放） |
| 紀錄 | 吃掉帥將、單回合最多吃子 |
