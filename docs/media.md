# 音樂、圖片與語音

## 背景音樂

只有站長可以提供音樂；玩家不能上傳曲目或輸入網址。

1. 把音訊檔放進 repository 根目錄下、被 Git 忽略的 `local-music/`。
2. 執行 `npm run music:import`（client 的 `predev` 與 `prebuild` 也會執行）。沒有監看機制：變更後請重新執行並重新整理。
3. 要發布時，建置後使用[前端發布工具](deployment.md#只發布前端)。

| 匯入規則 | 行為 |
| --- | --- |
| 格式 | MP3、OGG、OPUS、WAV、M4A、AAC、FLAC；遞迴搜尋，不分大小寫；其他檔案忽略 |
| 標題與順序 | 去掉副檔名的檔名；先放根目錄的檔案，再放各資料夾，各自依自然路徑順序排列；在檔名前加數字可以指定順序 |
| 分組 | 每個第一層資料夾是播放器清單中的一個分組；更深的資料夾併入該分組 |
| 曲目 ID | 相對路徑，所以搬移或重新命名會改變身分；輸出檔名含雜湊，可更新快取 |
| 音訊 | 保留原始位元組，不轉檔；各瀏覽器支援的編碼不同（MP3 最保險） |
| 封面 | 擷取檔案內嵌的封面：Ogg Opus／Vorbis（`METADATA_BLOCK_PICTURE`）、FLAC（`PICTURE` 區塊）、帶 ID3v2.2／2.3／2.4 標籤的檔案（`APIC`／`PIC`）；只讀檔頭，優先使用「正面封面」類型，否則取第一張。M4A、WAV、AAC 與沒有 ID3v2 的 MP3 沒有內嵌封面 |
| 封面備援 | 曲目沒有內嵌封面（或封面損毀）時，使用該曲目所在資料夾的 `cover.{jpg,jpeg,png,webp}`，其次是 `folder.*`（不分大小寫，不往上層找） |
| 封面輸出 | 以 `sharp` 置中裁成 160×160 的 WebP（品質 72，約 2–6 KB）；檔名 `imported-cover-<內容雜湊>.webp`，相同的封面只寫一份；目錄中的曲目以 `cover` 欄位指向它，沒有封面時省略此欄 |
| 驗證 | 結構、路徑與非空檔案；不檢查能否解碼。封面無法解碼時只警告並略過，曲目照常匯入 |
| 安全性 | 符號連結或空檔案會在目錄變更前就失敗；只移除匯入工具產生的過時輸出（含音訊與封面） |

- 自動產生且被 Git 忽略，**請勿編輯**：`client/src/audio/provided-music.generated.json` 與 `client/public/provided-music/imported-*`。全新的 checkout 播放清單是空的。
- 播放器控制：播放／暫停、上一首／下一首、單曲重複、依序或隨機播放。音量移到[音訊設定](#音訊設定)（音樂預設 50%）。新訪客以隨機模式與隨機曲目開始；儲存的音量、曲目、模式與分組選擇會在本機還原。
- 面板第一列是正在播放：封面圖（沒有封面時退回依專輯名稱產生的漸層色塊）、曲名、「專輯 · 第 n/m 首」與上一首／播放／下一首／播放模式（32px，觸控裝置 40px 並獨占一列）；「音訊設定」是右上角的滑桿圖示。專輯列 40px，前面是 28px 的專輯封面（取該專輯第一首有封面的曲目）、標示「32 首」；展開後曲目是 36px 的列，前面是 28px 圓角縮圖（沒有封面時是帶曲目編號的色塊），播放中的曲目在縮圖上疊跳動音柱（只用 transform，減少動態效果時靜止）並自動捲到視野內。縮圖延遲載入（`loading="lazy"`），不會阻擋面板開啟；圖片載入失敗時退回色塊。開始播放時也會以同一張圖更新瀏覽器的 Media Session（鎖定畫面與系統媒體控制）。換到另一張專輯時會自動展開它。分組可以收合（打開面板時只展開目前的分組），且每個分組都有核取方塊：取消勾選的專輯變灰，會被上一首／下一首、隨機與自動播放下一首跳過，但仍可點擊播放。至少會保留一個可播放的分組或根目錄曲目處於勾選狀態。
- 在新分頁開啟網站會開始播放。重新載入時，會保留該分頁中的暫停狀態（session storage），直到玩家再次按下播放。若瀏覽器阻擋自動播放，會等待可信任的使用者操作再播放；暫停會取消這次重試。切換路由或關閉面板時都會持續播放。重複使用同一個 audio 元素，讓瀏覽器的解鎖狀態延續到之後的曲目。
- 關閉音樂會暫停播放，也從不自動播放；在音樂面板按下播放會重新開啟。
- 輪到提醒是另外合成的提示音，預設開啟，不受音樂暫停影響，音量跟隨音效聲道。提醒會等到呈現截止時間，音訊被阻擋時直接丟棄，不會排隊。
  - 只有入座且輪到自己（或同時進行的階段還欠自己的動作：十三支理牌、21 點與十點半下注、拿破崙檢視、陸戰棋布陣、海戰棋擺放）才響；旁觀者、回放與已認輸的座位不響。判斷邏輯在 `client/src/hooks/use-turn-sound.ts`。
  - 棋類的提醒延後 260ms，排在交出回合的落子聲之後。棋類以「其他座位做過的動作數」判斷新回合：其他人全被跳過、回合直接回到自己時會再響一次；暗棋連吃、五子棋交換開局連下等自己的回合延續時不重複。
- 有人加入時，其他房間成員會聽到另一個上升的提示音；加入者本人聽不到。它跟隨回合提醒音的開關，音訊被阻擋時直接丟棄。
- 使用者操作（點擊，iOS 上為 touchend）會解鎖音訊。

## 音訊設定

「音訊設定」面板集中所有音量，從導覽列（窄畫面為頂端列）的音樂選單、手機遊戲選單、語音面板的「更多音量設定」，以及帳號頁的音效分頁開啟，每個入口都是同一個元件。短的橫向手機畫面上，面板改為兩欄，避免捲動。

| 聲道 | 內容 | 預設 |
| --- | --- | --- |
| 主音量 | 乘上其他所有聲道 | 開，100 |
| 背景音樂 | 音樂播放；關閉時暫停且不自動播放 | 開，50 |
| 音效 | 遊戲音效（出牌、pass、淘汰、開始、牌七斬擊與翻桌、擲骰、開骰、落子、吃子、翻棋與將軍）、回合提醒、加入提示與介面音效（含商店試聽）共用一條音量 | 開，100 |
| 語音聊天 | 所有人的整體輸出音量，再乘上語音面板的逐人音量 | 開，100 |

- 「回合提醒音」是音效聲道下的獨立開關，沒有自己的滑桿；關閉時回合提醒和加入提示都不會播放。
- 實際音量是主音量 × 聲道音量，任一開關關閉即靜音。商店試聽也走音效聲道，所以音效關閉時不會出聲。
- 設定只存在瀏覽器本機。舊的開關（`sound.effects`、`music.enabled`、`sound.turn`）與 `music.volume` 沿用原本的儲存鍵；新增的 `audio.master.*`、`audio.voice.*`、`sound.effects.volume` 缺少時使用預設值，無效或超出範圍的數值會修正到 0–100。
- 合成音效在每個 AudioContext 內經過「提升增益 → 軟上限 → 音效增益 → 主增益 → 喇叭」。背景音樂經由 `MediaElementAudioSourceNode` 與增益節點播放；iOS Safari 的 `HTMLMediaElement.volume` 是唯讀的，只有這條路徑的滑桿才會生效。
- 音效響度：
  - 離線量測（[`sound-pack-render.ts`](../server/tests/client/sound-pack-render.ts)）把每個提示算成取樣，單位是 150 Hz 高通後最響的 100 ms RMS（dBFS）。調整前，各音效包的同一個提示最多差 13 dB（例如出牌 −24 至 −37 dBFS），整體落在 −17 至 −38 dBFS；音樂預設音量 50% 時平均約 −21 dBFS，最響的 100 ms 約 −18 dBFS。
  - 每個提示有共用的目標響度（[`CUE_TARGET_DB`](../client/src/audio/sound-levels.ts)），每個音效包的每個提示再有一個逐項修正（`PACK_CUE_TRIM_DB`，−6 至 +12 dB）。`resolveSoundPack` 回傳套用修正後的副本，原始配方不變，所以安靜的配方被拉得最多、大聲的略降。更動配方後，`sound-levels.test.ts` 會失敗並指出偏離的提示，依量測值重新產生修正表。
  - 所有音效再統一提升 6 dB（[`EFFECTS_BOOST_DB`](../client/src/audio/mix.ts)），新增的軟上限讓同時疊加的提示（例如連發的出牌聲）不會削波：−6 dBFS 以下維持線性，之後以 tanh 曲線平滑逼近滿格，輸出永遠不超過滿格。軟上限在滑桿之前，調低音效或主音量仍會等比降低輸出。軟上限沒有過取樣，否則輸出濾波器的振鈴會讓峰值超過滿格。
  - 音樂與語音的音量不變，滑桿仍是 0–100，儲存的偏好也沒有變動；音效滑桿 100 因此比以前響 6 dB 以上。
- 音樂的 AudioContext 只在使用者手勢內建立或恢復（沿用現有的手勢解鎖事件）。進入 running 之前，音樂直接用 `<audio>` 播放並以 `element.volume` 調整音量，所以 iOS 上剛載入時的第一首歌，音量滑桿不會生效。沒有 Web Audio 的瀏覽器也使用這個後備方式。
- 語音聊天的整體音量同樣乘在每位對象的音量上；iOS 上語音沒有走 Web Audio，所以只有靜音與關閉會生效。

## 上傳

頭像、座位背景、牌桌背景、牌背與表情符號都以圖片上傳。

| 屬性 | 規則 |
| --- | --- |
| 格式 | PNG、JPEG、GIF、WebP |
| 解碼後大小 | 頭像與牌背 512 KiB；表情符號與背景 2 MiB（[`MEDIA_MAX_BYTES`](../shared/src/constants/media.ts)，用戶端與伺服器共用） |
| 請求大小 | 3 MiB 的 JSON 本文（proxy 與伺服器），足以容納 base64 編碼的 2 MiB 圖片 |
| 配額 | 每個帳號 100 MiB 的不重複圖片（[`MEDIA_QUOTA_BYTES`](../server/src/media/media-store.ts)）。重新上傳已擁有的圖片不另計；被替換的圖片仍會計入 |
| 儲存 | 不可變、以 SHA-256 內容定址的 ID，透過媒體 endpoint 讀取 |
| GIF | 在相同上限內保留原始位元組與動畫；不會縮小，所以超過上限就無法上傳 |
| 靜態縮放（用戶端） | 背景縮到長邊 1920 像素，牌背 512，表情符號 128；輸出 WebP，並以 JPEG（表情符號為 PNG）作為備援 |

- 上傳會在解析本文前檢查 Origin、工作階段與速率限制。錯誤：[API](api.md#狀態碼)。
- 用戶端縮放後先比對上限，超過就不送出，並顯示在地化訊息（上限與檔案大小，例如「頭像檔案上限為 512 KB，這個檔案是 1.3 MB。」）；伺服器仍會檢查，413 的訊息含上限（`Image is too large. The limit is 512 KB.`），用戶端會轉成同一則在地化訊息。頭像上傳按鈕旁標示上限。
- 牌桌背景與牌背只有擁有者看得到，從不廣播。
- 自訂牌背會覆蓋每一張背面朝上的牌（置中並裁切）。
- 圖片透明度為 20–100%（預設 100%），會讓圖片淡向主題的純色牌桌或牌面顏色。停止拖曳一小段時間後或放開滑桿時儲存。

## 官方外觀圖案

- 商店把原創的靜態 SVG 圖案打包在 `client/src/assets/shop/`；牌面組、座位框與聊天框、籌碼、棋子、棋盤、骰子、勝利特效與合成音效包則由 `client/src/cosmetics/` 下的程式碼產生。Vite 依設定的應用程式 base 解析資源網址；這些檔案不是上傳的媒體，也不是站方表情符號匯入工具的輸出，不佔用上傳配額。
- 官方牌背、牌桌背景與座位背景只在裝備時優先於仍保留的上傳圖片。圖片透明度也適用於官方的牌桌與牌面圖案。取消裝備即可恢復上傳圖片或主題；上傳圖片仍不另計。
- 商品擁有權、裝備與回復規則：[儲存](storage.md#外觀物品欄)。呈現方式：[介面](interface.md#外觀商店)。

## 個人表情符號庫

| 規則 | 行為 |
| --- | --- |
| 名稱 | 2–64 個 ASCII 英文字母、數字、`_`、`-`、`.`；必須以字母、數字或 `_` 開頭（[`EMOJI_NAME_PATTERN`](../shared/src/constants/emoji.ts)） |
| 大小寫 | 區分大小寫；較舊的 2–32 個字元小寫名稱仍然有效 |
| 上限 | 每個帳號 300 個項目，每次匯入最多 50 個；大型動態表情符號可能先用完配額 |
| 匯入命名 | 合法的檔名直接保留。否則把不合法的字元換成 `_`、合併連續重複、去掉開頭的分隔符號與結尾的 `_`，太短的名稱改為 `emoji`。重複時加上 `_2`、`_3`、… |

- 檔案與資料夾選擇器、拖放，以及貼上（表情符號庫取得焦點時）共用同一套匯入流程。
- 名稱篩選可以縮小格狀列表。選取模式會加上核取方塊，可用 Shift 點擊選取範圍；「全選」使用篩選後的列表，確認一次即可在一個請求中刪除所選項目。
- 刪除項目不會刪除已上傳的圖片。

## 房間聊天

- 文字去除前後空白後須為 1–500 個字元。`:name:` 先從寄件者的表情符號庫解析，再從[站方表情符號](#站方表情符號)解析，每則訊息最多 20 個名稱。
- 貼圖訊息是一個個人貼圖 ID、一個站方表情符號名稱，或一個官方商店貼圖 ID。每次傳送時，伺服器都會檢查寄件者是否擁有商店貼圖所屬的貼圖包；房間聊天與私訊使用相同的規則。用戶端不能傳送網址或其他帳號的圖片。收件者不需購買也能看到收到的貼圖。
- 傳送貼圖會保留文字草稿，並阻擋尚未完成的重複傳送。缺少的圖片會顯示無法使用的標示。
- 個人與站方貼圖重複使用表情符號圖片，放大顯示時可能比較模糊。商店貼圖使用打包的向量圖案與已翻譯的無障礙名稱。
- 不論語音狀態，聊天都可以使用。Payload：[API](api.md#socket-操作)；觀戰者頻道：[遊戲](games/common.md#旁觀者與上帝視角)。

## 站方表情符號

站長提供的表情符號，所有帳號都能以 `:name:` 文字或貼圖使用，顯示在選擇器中個人表情符號庫之後的分頁。文字中名稱相同時以個人表情符號優先（選擇器會隱藏被遮蔽的站方表情符號）；兩者都仍可作為貼圖使用。

1. 把圖片放進被 Git 忽略的 `local-emoji/`（可以有子資料夾）。
2. 執行 `npm run emoji:import`（client 的 `predev` 與 `prebuild` 也會在音樂之後執行）。資料夾為空或不存在時，會產生空的目錄，建置仍會成功。
3. 重新啟動開發伺服器。正式環境請執行[完整部署](deployment.md#建置與部署)：後端必須重新載入目錄，前端發布工具會拒絕已變更的目錄。

| 匯入規則 | 行為 |
| --- | --- |
| 格式 | `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`（不分大小寫）；輸出類型依檔案的 magic bytes 決定；其他或無法讀取的檔案會跳過 |
| 名稱 | 去掉副檔名的檔名，比照個人匯入正規化，上限 64 個字元；不到 2 個字元時改為 `emoji_<路徑雜湊的 6 個十六進位字元>` |
| 唯一性 | 跨資料夾與副檔名區分大小寫；合法的原始名稱優先，其餘依排序後的路徑順序加上 `_2`、`_3`、… |
| ≤ 2 MiB | 原樣發布 |
| > 2 MiB | 以 `sharp` 壓縮成最大 256 像素的 WebP（從不放大），保留每一個動畫影格；以更小的尺寸與更低的品質重試，最小到 96 像素，仍不行就跳過 |
| 輸出檔名 | `<name>-<content hash>.<type>`，內容改變時就會有新的網址 |
| 安全性 | 符號連結會在任何檔案被替換前就失敗；只移除匯入工具產生的過時輸出 |

- 匯入會印出壓縮後的大小，以及重新命名或跳過的警告。
- 自動產生且被 Git 忽略，**請勿編輯**：`shared/src/provided-emoji.generated.json`（由用戶端打包，伺服器啟動時讀取）與 `client/public/provided-emoji/`。
- 伺服器只接受列出的名稱。缺少目錄代表沒有站方表情符號；目錄無效時會停止啟動。
- 聊天紀錄保留原本的檔案。已移除的圖片會在資源寬限期內繼續發布，之後顯示為無法使用。

## 語音

桌機的等待房間與牌桌由[房間頁首](interface.md#房間頁首)的「語音」按鈕開啟側欄的「語音」分頁（頁首較窄時只剩麥克風圖示）；沒有側欄的精簡等待房間與手機牌桌（右上角的小麥克風按鈕與選單裡的「語音」）則開啟彈出面板。全域頁首沒有這個按鈕。關閉面板或在房間與遊戲之間切換時，語音工作階段會保留；按鈕上的綠點／琥珀色點代表已加入／加入中。

| 操作 | 行為 |
| --- | --- |
| 加入 | 需要明確操作；需要麥克風權限 |
| 麥克風（關閉） | 停止傳送；聲音關閉時打開麥克風也會一併打開聲音 |
| 聲音（關閉） | 停止播放遠端聲音並將麥克風靜音；重新開啟會恢復先前的靜音狀態（不影響音樂） |
| 控制項 | 點選參與者那一列，展開該玩家的靜音與音量；輸入與輸出裝置選擇 |
| 頁面切換 | 依房間成員資格延續到房間、遊戲與個人檔案頁面 |
| 離開、登出、斷線、被移除 | 釋放麥克風與 peer 連線 |
| 重新整理、多個分頁 | 需要重新加入；每個帳號一個分頁 |

- 最上方是狀態卡：圓點、狀態（語音已連線、已加入語音、部分連線失敗、連線失敗、尚未加入語音）與一句原因（人數與連線狀況，或錯誤原因）。卡片右側是一顆 36px 的小膠囊按鈕：未加入時是麥克風圖示加「加入」（失敗後是「重新連線」），加入中是「取消」，已加入是「離開語音」。不顯示房號。
- 接著是可收合的「裝置設定」列，預設收合，第二行摘要目前的裝置（「麥克風：系統預設・喇叭：系統預設」），加入前後都一樣。展開後是裝置列（圖示與深色自訂選單，取代瀏覽器灰色下拉）、麥克風下方的音量計與「測試」（自我監聽：未加入時暫時開啟所選麥克風，測試結束或收合即釋放，並播放給自己聽），以及喇叭旁的「播放測試音」。下方一直顯示語音總音量滑桿與「更多音量設定 ›」連結（開啟[音訊設定](#音訊設定)）。
- 已加入後狀態卡下方有「麥克風」（附音量計）、「聲音」兩個 36px 開關，關閉時轉為紅色；「聲音」關閉時標籤改為「聲音已關」。「重新加入」只在有玩家連線失敗時，以提示列上的動作出現。
- 成員列顯示頭像、自己的標記，以及靜音、聲音已關的小圖示；只有連線中或失敗時才顯示連線狀態。正在說話的人頭像有綠色光圈（以 `AnalyserNode` 讀取本機麥克風與每位對象的串流，一個共用的 animation frame 迴圈驅動；音量計只改 transform，光圈只改 opacity）。自己的列右側是小音量計。
- 點選（或按 Enter、空白鍵）其他玩家的列會展開該玩家的音量；同一時間只展開一列，列按鈕帶有 `aria-expanded`。每位其他玩家的列尾有一鍵靜音按鈕（`aria-pressed`）。
- 伺服器只對已加入語音的人廣播成員，所以未加入時看不到誰在語音中。
- 觀戰者靜音、觀戰者被靜音、瀏覽器擋自動播放等提示都是單行提示列。

- 點對點的 WebRTC 音訊，最多支援十六位房間成員（八個座位加八位旁觀者，[`MAX_ROOM_MEMBERS`](../shared/src/constants/game-rules.ts)）。對局中入座玩家聽不到觀戰者（[遊戲](games/common.md#旁觀者與上帝視角)）。
- Socket.IO 只轉送經過驗證的 signaling（[API](api.md#語音-signaling)）。**語音從不錄音或儲存。**
- 麥克風需要 HTTPS 或 localhost。即使已連線，權限、自動播放限制或缺少裝置都可能阻擋音訊。
- 每次加入都會取得新的 peer ID，所以過時的 signal 不會進入新的通話。peer 錯誤彼此隔離；重新加入會取代失敗的連線並保留偏好設定。
- 重新整理後，用戶端最多重試 45 秒，且不會搶走其他使用中分頁的語音。等待時間、訊息大小與佇列都有上限。

**ICE 設定**

預設為 `stun:stun.l.google.com:19302`。限制較嚴的 NAT 與防火牆需要 TURN relay。在 `client/.env.local` 設定 `VITE_WEBRTC_ICE_SERVERS`，再重新建置並部署：

```dotenv
VITE_WEBRTC_ICE_SERVERS=[{"urls":"stun:stun.example.com:3478"},{"urls":"turn:turn.example.com:3478","username":"browser-user","credential":"browser-credential"}]
```

- 這個值是**公開的**。請使用短期或受限制的 TURN 憑證，絕對不要放私密金鑰。
- 最多八個伺服器、十六個網址；scheme 為 `stun:`、`stuns:`、`turn:`、`turns:`。設定無效時會顯示錯誤。
- 合成的本機串流無法驗證真實的麥克風，也無法驗證跨網路的路由。
