# 商業營運 Roadmap

目標：經營可持續盈利的多人牌類遊戲服務，成本包含金流、基礎設施、內容、獲客、客服與營運工時。

**已確認：台灣優先，先營運網頁版。** 建議以朋友群與社團的私人牌桌切入，透過封測選出一至兩款獲客主力；先驗證回流與付費意願，再投資公開配對、新遊戲或手機商店。受眾與盈利模式仍待市場驗證，人力與預算待負責人決定。

本文件只保留未完成工作、候選方案與必要決策，不承諾全部實作或完成日期。完成後更新對應指南並移除項目；編號不重排、不重用。暫時執行計畫放在 Git 忽略的 `.plan/`。

規劃基準為 2026-11-05 的程式庫核對；現行功能見[遊戲規則](games/README.md)、[介面](interface.md)與[儲存](storage.md)。功能或部署設定已存在，不代表正式環境容量、備份、安全、授權或營運驗收已通過。

## 產品與盈利原則

- 付費不影響合法操作、計時與競技結果；基本加入、遊玩、帳號復原、資安、檢舉及資料權利申請維持免費。
- 對局籌碼、帳號金幣與付費權益分開。金幣只獎勵完局，不獎勵獲勝；籌碼與金幣皆不可購買、轉讓、兌現或用於有價賭注，不協助外部賭博。
- 商品與訂閱直接標價，權益由伺服器判定；不採用機率型獎勵、體力限制、付費參賽或公開天梯，排行限牌友圈內。
- 保留已取得的外觀擁有權、穩定商品 ID 與現有免費上傳。販售前定義免費／付費目錄；更動免費權益須由負責人決定並訂定過渡政策。
- 開放陌生人同桌前，伺服器須過濾觀戰者／淘汰玩家的未公開手牌；擴大獲客前檢查戰績與隱私預設值。外部通訊串通仍需另行處理。

## 上線階段與驗收門檻

P0 為該階段必要條件；P1 為後續改善。每次實驗先確定負責人、支出上限、觀察期間及繼續／停止條件。

### 階段 A：有人數上限的邀請封測

驗證不同群組能順利完局並主動回來；不開放真錢付款或全面陌生人找桌。

| 編號 | 優先級 | 工作與驗收條件 |
| --- | --- | --- |
| A1 | P0 | 指定營運／客服負責人、容量與支出上限，確認主機／網域的商用條件 |
| A2 | P0 | 確認素材權利、條款／隱私／分級告知，提供可執行的帳號復原與資料請求流程；可先人工處理 |
| A3 | P0 | 提供首次開桌引導與重連／逾時說明 |
| A4 | P0 | 以代表性資料與負載驗證容量；將異地完整資料庫／媒體／回放備份還原至隔離環境，演練維護與回復 |
| A5 | P0 | 建立符合隱私要求的邀請 → 加入 → 首次完局 → 回流量測，區分群組、bot 與自然獲客 |
| A6 | P1 | 手機支援模式以實際 iOS Safari／Android Chrome 驗證旋轉、前後景、弱網路、session 過期與完整遊玩；電腦限定模式驗證手機提示與入口限制 |

建議以 5–10 個獨立群組試用四週。多個群組無須提醒便回來、重大缺陷已解決，且房主能指出具體付費需求，再進入下一階段；若常需人工救援，先改善核心體驗。

### 階段 B：公開免費營運

安全接待陌生玩家並量測留存；自動配對不是必要條件。

| 編號 | 優先級 | 工作與驗收條件 |
| --- | --- | --- |
| B1 | P0 | 發布經審查的條款／隱私／社群守則、分級／年齡與業者資訊、客服管道，保存同意版本 |
| B2 | P0 | 完成檢舉、下架／處分與申訴流程，涵蓋聊天、私訊、個人資料及上傳；保護管理權限、撤銷 session 並保留稽核 |
| B3 | P0 | 提供身分驗證與限時單次帳號復原；支援資料副本／刪除、保存例外及備份還原後再次刪除。無須同時完成 LINE／Google 登入 |
| B4 | P0 | 驗證觀戰／淘汰快照、事件、重連、對外紀錄與回放均不洩漏未公開手牌；完成前維持邀請限定 |
| B5 | P0 | 監控外部 HTTPS／Socket、寫入、延遲、記憶體、磁碟／媒體成長與備份新鮮度；驗證告警送達、事故及還原流程 |
| B6 | P0 | 停用無法管理的上傳／語音管道；上傳須有伺服器解碼、像素／影格限制與審核下架；語音須有跨網路測試與受限短效 TURN 憑證 |
| B7 | P1 | 公開產品介紹、說明／公告與可追蹤邀請，先招募社團與固定活動 |
| B8 | P1 | 試辦可依隱私／容量／房規篩選的房間列表，揭露 bot 與等待上限；需求足夠再加配對 |
| B9 | P1 | 評估離房／斷線逾時的接手或棄權，定義戰績、獎勵與代打揭露；現行斷線 60 秒會中止未完局 |
| B10 | P1 | 強化防濫用、更新依賴，確認相容後啟用強制 CSP；用戶端縮圖不能取代上傳安全檢查 |

完成條件：檢舉與帳號請求可完整處理、隱私測試通過、備份可還原、告警可引導處理，尖峰負載符合容量上限。至少觀察四批每週新玩家；完局與群組回流仍差時，不購買大規模流量。

### 階段 C：網頁版付費試營運

先驗證一種方案與一家金流。私人桌可在 A 後試辦收費，但須先通過 B 中適用的法律、帳號、安全與維運門檻。

| 編號 | 優先級 | 工作與驗收條件 |
| --- | --- | --- |
| C1 | P0 | 收款前確認營業／稅務／金流資格、價格、收據／發票、退款與取消條款；人工銷售亦適用 |
| C2 | P0 | 審查既有引擎的帳務 schema、transaction、稽核與恢復；保留 Repository 約束、金幣／擁有權，驗證遷移與回復 |
| C3 | P0 | 伺服器定價、驗證 callback、唯一外部交易 ID、原子更新訂單／權益，處理重複、延遲與亂序事件 |
| C4 | P0 | 處理待付款／失敗／已付款／退款／爭議款、權益撤銷／降級與到期／取消，保留稽核並每日對帳 |
| C5 | P0 | 驗證重試／當機、漏發權益、無效 callback、退款／爭議款及還原；對帳修復外部付款與本地提交差異 |
| C6 | P1 | 試售原創外觀包或有期限的房主方案，觀察使用與續用後再擴充目錄／自動續訂 |
| C7 | P1 | 金幣可換取付費內容替代品前，定義獲取上限、獎勵憑據與防 bot／分身／快速完局刷獎勵措施 |

完成條件：sandbox 與受控正式購買／退款成功，訂單、權益與金流報表一致，客服能補救漏發；收入高於變動成本。盈利另須扣除固定成本及開發／營運工時。

依已驗證需求選擇方向，不同時全面推進。

| 編號 | 方向 | 前提 |
| --- | --- | --- |

## 盈利模式與成本評估

| 模式 | 驗證重點 |
| --- | --- |
| 原創外觀包 | 優先驗證他人可見的框／名牌／貼圖，評估免費上傳與既有商品的替代性 |
| 房主／社團方案 | 以排程、共用主題與摘要等持續價值換取群組付費 |
| 教學／分析訂閱 | 先驗證主力遊戲需求、正確性與分析成本 |
| 組織活動 | 找到實際買方，計入銷售、準備與現場支援成本 |

依獲客來源與玩家批次追蹤已結算營收、退款、金流／商店費、適用稅額及變動服務／內容／客服成本。損益兩平付費人數＝每月固定成本 ÷ 每位付費者的每月貢獻；成本須計入未支薪工時。以實際續用與獲客成本評估投資，小樣本不推估終身價值。

### 新類型的實作取捨

- **裝置：** 已確認手機支援不作為新模式的必要條件。需要大型桌面、畫布或多份線索的模式可設為電腦限定；手機在選擇與加入時提示「請使用電腦遊玩」、阻擋進入並提供返回入口。實作時同步調整[新增遊戲驗收](architecture.md#新增遊戲)的手機要求，依模式宣告支援裝置。
- **bot：** 延續可補 bot 的方向時，優先評估 E20，再選 E22／E23。E18／E24／E25／E27 可評估真人限定，但是否放寬每款遊戲可補 bot，仍待決定。
- **內容與投入：** 真人聚會可先試文字聯想／傳畫猜詞，合作解謎待有明確需求再投入。人數與規模均為設計建議，不是市場或工期保證；手機不支援不代表規則、bot 與內容維護成本降低。既有品牌只作機制參考，素材使用依授權原則審查。

實驗順序：

1. 補齊量測後，逐項驗證 R14、R15、R2 與既有成長回饋；結算聚焦一個自選目標，保留終極稱號。短系列賽先定義退出、平手、戰績與獎勵。
2. 固定群組：R16 → R6／R4 → R5，先驗證下次開桌意願。
3. 新鮮感：先試 R17／R7，再評估 R9；好友不在線是主要離開原因時，提前 R18。
4. R9／R10 擇一驗證，再評估角色劇情；大型模式不與輕量改善同時全面投入。

沿用封測群組建立基準、逐項觀察完整週期並訪談房主。追蹤續局、回流完局與反效果；不把登入領獎當有效遊玩，也不以小樣本承諾提升幅度。

量測須標記獲客來源、玩家批次、主力遊戲及 bot／真人桌，顯示樣本數並排除尚未完整觀察的期間：

- **回流與續玩：** 首次完局後第 1／7／28／30 個台灣日再次完局、群組跨週同桌、同次造訪再開局；先固定造訪與觀察窗口。
- **參與與健康度：** 前景且本人未代打的對局時間、完局／中離／斷線／逾時、等待與延遲 p95；排除閒置，檢查刷獎勵及任務負擔。
- **維運與商業：** 可用率、寫入失敗／耗時、備份時間差、還原 RPO／RTO、媒體／TURN 成本、付費／續用、毛利、退款與工時。

依資料設定服務目標與容量，演練可接受資料損失時間（RPO）及恢復時間（RTO）；付費訂單另需恢復與對帳。固定回傳 `ok` 的健康檢查不足以證明可寫入或可遊玩。

待處理限制：

- 公開雜湊媒體 URL 與長效快取不具身分保護；下架／刪除須涵蓋提供端、快取、備份及引用。安全清理不得刪除仍被訊息引用的檔案，並須設定全站容量上限。
- 房主踢人不等於站方封禁；處分須涵蓋重新加入、session 與分身濫用。
- 付款 webhook 使用獨立供應商驗證，不全面停用瀏覽器 Origin 防護。
- 分析／log 不記錄密碼、session token、私人手牌、私訊與語音；保護維運及備份存取。

完成後將操作程序更新至[部署](deployment.md)、[儲存](storage.md)及[媒體](media.md)指南。
