# Roadmap

本文件規劃 Card Together 從朋友間的私人牌桌轉型為公開營運、有營收的服務，記錄方向、階段順序和
完成條件。詳細任務計畫放在被 Git 忽略的 `.plan/`。法規內容是需要律師確認的風險提醒，不是法律意見。

## 現況缺口

| 面向 | 缺口 |
| --- | --- |
| 大廳 | 只能用房號加入，沒有公開房間列表或配對 |
| 帳號 | 沒有 email、忘記密碼、刪除帳號、年齡資訊或第三方登入 |
| 社交與媒體 | 沒有檢舉、封鎖或管理工具；上傳圖片未經審核；站方音樂和 emoji 授權未盤點 |
| 儲存 | 單一 process 的 JSON 檔，沒有 transaction，限制同時在線量 |
| 維運 | 沒有異地備份、監控、告警，也沒有語音用的 TURN 中繼 |
| 遊戲 | 最多四個座位；bot 沒有難度分級；觀戰者可看到所有手牌 |

對局籌碼每局重設；帳號金幣只在完成對局時固定增加，與輸贏無關，也不能購買。這兩點應該保留
（見原則 1）。

## 基本原則

1. **遊戲結果不連結真實價值。** 對局籌碼不跨局累積；帳號金幣只能靠完成對局取得，數量與輸贏無關，
   不能購買、轉讓、換成現金或下注。刑法第 266 條處罰網路賭博財物，分級規定也把遊戲結果會增減
   虛擬遊戲幣的牌類遊戲列為輔 15 級。
2. **不賣影響輸贏的東西。** 只賣外觀和便利功能。
3. **不賣機率型商品。** 付費抽獎依法須以百分比揭露機率；商品一律直接標價。
4. **伺服器權威不變。** 權益、排名和購買都由伺服器判定。
5. **先穩定維運再擴大成長。** 達成一個階段的完成條件，才推進下一階段。

## Phase 0：上線準備

目標：可以合法、安全地開放給陌生玩家。

- **法務：** 營業登記；中英文使用條款、隱私權政策和社群守則；確認遊戲分級，必要時加入年齡確認；
  盤點牌面圖（LGPL，保留授權聲明）、音樂和 emoji 的商業授權；決定程式碼是否繼續公開。
- **帳號：** email 驗證、忘記密碼、刪除帳號與匯出資料；LINE 和 Google 登入。
- **信任與安全：** 檢舉、靜音、封鎖；管理後台與操作稽核紀錄；聊天過濾；上傳圖片需審核；
  公開房間預設關閉語音。
- **維運：** 改用允許商業用途的主機；異地加密備份並演練還原；監控與告警；TURN 中繼。

**完成條件：** 法律文件已發布、檢舉可處理到封鎖、異地備份可還原、跨行動網路語音可連線。

## Phase 1：公開測試

目標：陌生玩家能很快湊滿一桌，而且願意回來。

- **儲存遷移：** 沿用 Repository 介面改用 SQL 資料庫，是 Phase 2 金流的前提。流程依照
  [storage](storage.md)。
- **找到牌局：** 公開房間列表；快速配對，空位逾時由 bot 補上；邀請連結。
- **新手體驗：** 各遊戲互動教學；PWA；遊戲介紹頁。
- **數據：** 註冊漏斗、湊桌時間、留存。

**完成條件：** SQL 遷移通過 production 資料驗證；湊桌時間和留存開始每週追蹤。

## Phase 2：營利

目標：在不影響公平性的前提下取得營收。

- **交易基礎：** 訂單與權益帳本（同一個 transaction 完成）、可重複處理的金流 callback、退款與對帳；
  選用能開電子發票的台灣金流業者（如綠界、藍新、TapPay）。
- **外觀商店：** 牌背、桌布、貼圖包、頭像框、主題。現有的外觀系統已能顯示，只需加上擁有權。
- **金幣用途：** 可用來換取部分外觀，讓免費玩家也有目標；不開放用錢購買金幣。
- **贊助訂閱：** 免廣告、較大上傳額度、完整統計、徽章、賽後分析。
- **廣告（可選）：** 只放大廳，訂閱者不顯示。

**完成條件：** 購買、退款、發票在 sandbox 和 production 都通過，帳本和金流報表一致。

## Phase 3：社群與留存

目標：讓玩家每週回來並邀請朋友。

- **積分賽：** 技巧型遊戲的賽季積分和排行榜，不放 bot，使用標準規則。
- **回放與公開觀戰：** 回放從公開 log 重建；公開觀戰前先處理 god view 洩漏（見[公平與防作弊](#公平與防作弊)）。
- **成就與免費錦標賽：** 獎勵只限徽章和外觀。
- **遊戲模組化：** 把每款遊戲的規則、驗證、bot 和畫面集中成一個模組，降低新增遊戲的成本。

**完成條件：** 賽季自動運作；回放和觀戰不洩漏私人手牌（有測試涵蓋）。

## Phase 4：規模化

- 多 process 水平擴展（需先做設計審查，會改變單一 process 擁有資料的規則）與 CDN。
- 上架手機商店；先確認各商店對牌類與模擬博弈內容的規定。
- 社群與企業私人活動，作為第二條營收來源。

## 遊戲內容發展方向

新遊戲建議在 Phase 3 遊戲模組化後再大量加入。

### 新遊戲候選

| 遊戲 | 可重用 | 技術前提 |
| --- | --- | --- |
| 紅心、拱豬 | Bridge 的吃墩邏輯和 bot | 無，成本最低 |
| 黑桃王（Spades） | Bridge 的叫牌、吃墩、隊伍座位 | 無 |
| 抽鬼牌、釣魚 | 彈性座位 | 抽鬼牌需要鬼牌 |
| 鬥地主、跑得快 | 大老二的牌型判定和 bot | 各遊戲自訂人數、三人座位方位 |
| 升級（拖拉機） | 隊伍座位、吃墩 | 兩副牌加鬼牌 |
| 心臟病（拍牌） | 房間、聊天 | 即時判定與延遲補償，需先評估 |
| 台灣十六張麻將 | 房間、計時、bot 排程 | 全新牌具與美術，風險較高；屬獨立產品決策 |

避免使用 UNO 等商標名稱或照搬其規則。

### 深化現有遊戲

- **房規框架：** 把排七屠龍、99 雙副牌、21 點玩家當莊整合成共用機制，再加入大老二、Bridge 計分、
  德州撲克盲注等選項。房規記入對戰紀錄，統計和排名只比較同規則對局。
- **新模式：** 快速局、複式橋牌（多桌同牌比成績）、每日挑戰（全站同一副固定種子的牌）、牌局謎題、
  節慶限時活動。
- **德州撲克和 21 點：** 擴充到 5–6 人。

### Bot 與 AI

- 難度分級：困難模式從己方手牌和公開資訊抽樣推估，不讀對手真實手牌。
- 不同個性（保守、激進），以及賽後分析（只在對局結束後提供）。
- 有 bot 的對局維持不計入戰績。

### 公平與防作弊

- **god view：** 觀戰者和已淘汰玩家能看到所有手牌，陌生人可透過外部管道通報。公開房間和積分桌
  應延遲顯示或只顯示公開資訊。
- **共謀偵測：** 積分賽累積資料後偵測固定組合的放水模式。
- **可驗證洗牌（可選）：** 開局前公布種子雜湊，局後公開種子。

### 無障礙

四色牌面、大字模式、螢幕閱讀器播報出牌。

## 指標

| 類別 | 指標 |
| --- | --- |
| 成長 | 註冊完成率、首次開局時間、湊桌時間 |
| 留存 | 第 1／7／30 天留存、DAU/MAU |
| 營收 | 付費轉換率、每位付費玩家營收、訂閱流失率 |
| 健康度 | 可用率、操作延遲 p95、每千局檢舉數 |

## 主要風險

| 風險 | 因應 |
| --- | --- |
| 德州撲克或 21 點被視為賭博或從嚴分級 | 原則 1、律師審查、可依通路關閉特定遊戲 |
| 聊天、上傳、語音遭濫用 | 公開上線前完成 Phase 0 信任與安全 |
| 上線初期湊不滿桌 | 快速配對加 bot 補位、先經營種子社群 |
| 儲存或主機故障 | 異地備份、遷移到 SQL |
| 素材授權爭議 | Phase 0 盤點授權 |

## 待決事項

- 營運主體、預算和團隊人數。
- 只做台灣，或進入其他地區。
- 德州撲克和 21 點是否保留在公開版和 app 版。
- 金幣防刷：bot 局也會給金幣，若金幣可換取外觀，可設每日上限或只計真人對局。
- 免費自訂上傳與付費外觀如何並存：維持免費加審核、改為訂閱福利，或免費玩家只用內建款式。
- 開始營利後的程式碼公開與授權方式。
